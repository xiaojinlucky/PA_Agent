## 1. 产品定位

PA_Agent 不是缩小版券商软件，也不再只是 AI K 线分析工具。

正式定位为

> AI 驱动的价格行为自动交易控制台

产品主线只有一条

> 行情收盘 → PA 价格行为分析 → 程序规则校验 → 交易监督智能体审批 → 自动计算仓位和杠杆 → 自动下单 → 自动保护 → 自动加仓、减仓、反手与离场 → 自动复盘

用户正常运行时不需要逐笔确认订单。人工主要负责配置、启动、暂停和紧急处置。

## 2. 产品目标

### 2.1 第一阶段目标

完成以下闭环并支持无人值守运行

- 使用 OKX 已有行情数据源读取 XAU-USDT-SWAP 15 分钟 K 线
- 每根已收盘 K 线只触发一次分析
- PA 分析智能体自动给出方向、入场、止损、TP1、TP2 和信心
- 交易监督智能体读取原始信号、最新行情、账户、订单、持仓、盈亏和保护状态
- 监督智能体可以放行、拒绝、继续持有、加仓、减仓、平仓或平仓反手
- 所有实际券商操作统一通过 PA 执行层完成
- Windows 重启后自动恢复后台运行
- 关闭 GUI 后后台继续运行
- 支持暂停新开仓与紧急清仓
- 支持完整交易生命周期复盘

### 2.2 最终目标

在不推翻第一阶段架构的前提下扩展到

- 多品种
- 多策略
- 多账户
- OKX 现货与永续
- Longbridge 综合账户、日内融资子账户和模拟账户
- 组合级风险预算与策略隔离

## 3. 非目标

首版不做以下内容

- 不做新闻、社区、研报和资讯门户
- 不做完整盘口终端
- 不做券商式人工下单面板
- 不允许人工在 PA 专用账户中创建与 PA 无关的新仓
- 不自动接管外部系统创建的仓位
- 不让大模型直接调用 OKX 或 Longbridge API
- 不让两个智能体分别维护两套订单账本
- 不把 MT5 黄金价格直接映射成 OKX 永续订单价格
- 不从零新增 OKX 行情源，当前任务是审核、验收和完善现有链路

## 5. 核心产品原则

### 5.1 一个交易闭环，不做两个并列中心

行情、PA 分析、监督智能体、风险、订单和持仓必须显示为同一条交易链。

主界面第一眼回答五个问题

1. 系统是否正在自动运行
2. 当前 PA 对市场怎么看
3. 监督智能体是否放行或如何管理
4. 账户当前有什么仓位和风险
5. 下一步系统准备做什么

### 5.2 AI 决定交易意图，程序负责准确执行

PA 分析智能体负责市场机会。

交易监督智能体负责账户是否适合执行，以及持仓后续如何管理。

确定性程序负责

- 账户和品种
- 仓位数量
- 杠杆
- 保证金模式
- 订单参数
- 客户订单号
- 账本
- 券商调用
- 幂等、对账和恢复

确定性程序还必须保存每一次决策所使用的行情、账户、持仓、模型、规则和合约规格快照，并在状态变化或快照过期后拒绝继续使用旧结论。

自动分析协调器、两个智能体和 GUI 都不得持有券商密钥、构造券商适配器或直接发送券商请求。唯一允许创建执行适配器并写入券商的进程是 `ExecutionWorker`；其他模块只能写入受校验、可审计、可幂等的持久化命令。

### 5.3 中文优先

所有页面、状态、按钮和提示以中文为主。只在下列场景保留英文

- 精确品种代码，如 XAU-USDT-SWAP
- 精确模型 ID
- API、Token、TP1、TP2、OKX、Longbridge
- 必须与券商或代码一致的状态标识

### 5.4 进攻式运行，确定性约束

产品目标是自动捕捉机会、动态复利和趋势加仓。

风险规则不应变成逐笔人工审批，但必须作为程序中的明确边界，自动执行，不依赖用户每次确认。

## 6. 第一阶段固定交易规则

### 6.1 账户

- 使用 PA 专用 OKX 子账户
- 使用 PA 专用 API Key
- 其他系统不得使用该子账户
- 子账户首期只存放 USDT
- 不把主账户或其他子账户净值纳入风险基数
- 外部仓位不接管，不修改，不平仓，不补保护
- 发现外部同品种仓位时，阻止 PA 新增该品种风险

### 6.2 品种与周期

- 行情源，OKX
- 分析品种，XAU-USDT-SWAP
- 交易品种，XAU-USDT-SWAP
- 周期，15 分钟
- 允许做多和做空
- 首期不开放任意周期自由切换作为正式自动交易配置

### 6.3 持仓和保证金

- 净持仓模式
- 全仓模式
- 同一时刻只保留一个净方向
- 同方向信号允许加仓
- 反向信号可以继续持有、仅平仓或平仓反手
- 反手必须先确认旧仓数量归零，再重新计算新方向仓位

### 6.4 风险和仓位

每个完整交易生命周期（首仓、其后的同向加仓、以及最终退出）只拥有一份风险预算。反手在旧仓已确认归零后才开始新的生命周期和新的预算。

```text
生命周期风险上限 = 创建该生命周期时的已确认 PA 子账户净值 × 10%
本次可用风险 = 生命周期风险上限 − 当前已确认仓位在统一止损下的最坏预计亏损
```

首仓前、每次加仓前和反手新开仓前都必须重新读取账户与合约规格；但加仓不得把 10% 当成一笔新的独立预算。仓位计算必须基于冻结快照中的入场价、统一止损、`ctVal`、`lotSz`、`minSz`、费用和保守滑点假设，并向下取到合法张数。

```text
单张最坏损失 = 合约规格换算后的入场到统一止损损失 + 预计费用 + 保守滑点
风险张数 = 本次可用风险 ÷ 单张最坏损失
最终张数 = 向下取整到 lotSz 的 min（风险张数，OKX 当前最大可开张数）
```

补充规则

- 10% 是生命周期的最坏损失上限，不要求每次都用满
- 若最终张数低于 `minSz`、快照过期、损失无法可靠换算或最大可开张数读取失败，则不创建新风险
- 不为了吃满预算而移动 PA 给出的结构止损；监督智能体也不得通过放宽止损扩大既有风险上限
- 购买力必须使用 OKX 实时最大可开张数，不用简单可用余额代替
- 新生命周期的净值基数随已确认盈亏变化；同一生命周期的预算基数不得因加仓而重置

### 6.5 动态杠杆

动态杠杆属于目标能力，只有在 OKX 官方接口语义、账户模式和本地适配器实现都完成核验后才可启用。第一阶段固定规则如下。

1. 只允许在该品种无 PA 仓位、无外部冲突仓位、无未决执行命令时调整杠杆。
2. 先按本节风险公式计算目标张数，再在交易所允许范围内计算所需的最低杠杆。
3. 杠杆变更必须作为 `ExecutionWorker` 的持久化、可对账命令执行；执行后重新读取并确认实际杠杆和最大可开张数。
4. 只有确认成功且新快照仍有效，才可按重新读取的最大可开张数生成入场计划；任何结果未知、失败或规格变化都停止新风险。
5. 持仓期间第一阶段不自动调整杠杆。监督智能体只能提出管理意图，不能指定任意杠杆值或直接调用接口。

### 输入

- XAU-USDT-SWAP 最新已收盘 15 分钟 K 线
- PA 已有指标与价格行为特征
- 上一轮分析和方案连续性
- 当前持仓摘要，仅用于理解当前上下文，不直接操作账户
- 策略文件和经验库

### 输出

- 市场状态
- 方向
- 下单类型
- 入场价
- 止损价
- TP1
- TP2
- 交易信心
- 交易理由
- 方案失效条件

### 权限

- 可以提出交易机会
- 不能决定账户
- 不能决定最终数量
- 不能决定 API 参数
- 不能直接调用券商

## 7.2 交易监督智能体

### 输入

- PA 原始信号和理由
- 入场价、止损、TP1、TP2
- 开仓后的最新 K 线
- 当前账户净值、购买力和风险
- 当前订单、成交、持仓、平均成本和盈亏
- 保护单状态
- 之前执行过的管理动作

### 调用时机

- 每根 15 分钟 K 线收盘
- 入场成交
- 部分成交
- 保护单异常
- 订单状态未知
- TP1 成交
- 持仓和本地账本不一致
- 账户风险状态明显变化

### 开仓前权限

允许输出

- 放行
- 暂缓
- 拒绝
- 暂停后续新开仓

不允许

- 把做多改成做空
- 把做空改成做多
- 自行指定账户
- 自行指定最终数量和杠杆

### 持仓后权限

允许输出

- 继续持有
- 同方向加仓
- 减仓
- 全部平仓
- 平仓并反手
- 收紧止损
- 移到保本位
- 移到结构低点或高点
- 修改 TP1、TP2
- 取消固定 TP2，改为逐 K 管理
- 暂停新开仓

不允许

- 通过放宽止损扩大已批准的总风险
- 直接调用券商 API
- 操作无法证明属于 PA 的仓位

### 7.2.1 监督结论的固定契约

监督智能体只能产生结构化的交易意图，不能输出自由文本后由程序猜测执行方式。每个结论必须包含：目标信号或生命周期 ID、版本号、输入快照摘要、原因、有效期和下列唯一动作之一。

- 新风险：放行、暂缓、拒绝、暂停后续新开仓
- 已有 PA 仓位：继续持有、请求同向加仓、请求减仓、请求全部离场、请求平仓后反手、请求调整保护

动作参数只可填写已定义字段，例如统一止损、TP 分配、减仓比例或反手方向；不存在“自定义订单”“任意数量”“任意杠杆”这类逃逸字段。确定性校验必须再次确认动作仍对应同一快照、同一生命周期和当前状态。智能体结论失效、冲突或超时，一律停止新增风险；不得阻断已有保护、对账和退出。

## 7.3 模型档案

目标架构中，两个智能体分别绑定独立的角色档案与主/备用档案映射；当前仓库只有一个全局活动模型档案，这项角色映射需要新增而非假定已经存在。

- 主模型档案
- 备用模型档案
- 上下文上限
- Thinking
- 推理强度
- 超时和重试

两个智能体可以绑定同一个模型档案，也可以使用不同模型。

每次结果必须保存实际使用的接入方式、角色档案、模型 ID、参数快照、提示词版本和输入快照摘要。备用模型只能使用同一份冻结输入和同一份输出契约，不能为了“给出答案”混入新的行情或账户状态。

## 7.4 三层失败处理

1. 主模型
2. 备用模型
3. 确定性兜底

确定性兜底规则

- 新开仓审批失败，本轮信号不执行
- 已有正常保护的持仓，维持原保护并继续轮询
- 保护缺失，执行已有确定性补保护或减险流程
- 反手旧仓未归零，不开新方向
- 模型失败不停止券商订单查询和保护单运行

## 8. 自动交易循环

### 8.1 正常循环

```text
等待 15 分钟 K 线确认收盘
→ 获取并校验最新 OKX K 线
→ 以 `账户 + 品种 + 周期 + 已收盘 K 线开盘时间 + 策略版本` 作为唯一键抢占处理权
→ PA 完整或增量分析
→ 生成持久信号记录
→ 确定性程序校验
→ 监督智能体审批
→ 刷新账户净值和最大可开张数
→ 计算仓位和动态杠杆
→ 生成不可变执行计划
→ ExecutionWorker 执行
→ 订单、保护和账户状态持续回写
```

自动循环由新增的**自动分析协调器**负责：它只读取行情、账户快照和账本状态，调用智能体，并创建受校验的持久化命令；它不持有券商凭据、不导入券商客户端、不拥有券商写权限。每一步都必须记录开始、成功、失败和输入版本。K 线未确认收盘、重复键已完成、快照不完整、数据源不健康、处理权超时或状态不一致时，都不得创建新的执行计划。重试只能重试同一唯一键的未完成读取/分析步骤，不能重复提交订单。

### 8.2 同方向加仓

新的同方向信号出现后，监督智能体可以批准加仓。

```text
整笔交易风险上限 = 该生命周期创建时的已确认净值 × 10%
剩余风险预算 = 风险上限 − 当前已确认仓位在统一止损下的最坏预计亏损
新增张数 = 向下取整到合法张数的 min（剩余风险预算对应张数，实时最大可开张数）
```

加仓成交后

- 重新计算加权平均成本
- 合并为同一条交易生命周期
- 统一重建止损、TP1、TP2
- 历次首仓和加仓节点保留为事件
- 不建立彼此冲突的多套保护
- 加仓、统一保护替换和成交回写必须由同一个生命周期锁串行完成；在锁释放并对账成功前，拒绝新的管理动作

### 8.3 反向信号

监督智能体可选择

- 继续持有
- 仅平仓
- 平仓并反手

平仓并反手必须按以下顺序

```text
请求旧仓离场
→ 确认旧仓归零
→ 旧交易进入已完成
→ 重新读取净值和购买力
→ 重新计算反向仓位和杠杆
→ 创建新方向执行计划
→ 自动入场和建立保护
```

任何一步出现部分成交、结果未知、外部仓位、保护异常或账本不一致时，反手流程停在当前步骤并进入对账，绝不预先提交新方向订单。

### 8.4 保护和止盈

监督智能体可以从预设分批方案中选择

- 70% / 30%
- 50% / 50%
- 30% / 70%
- 100% / 0%
- TP1 小幅减仓，剩余取消固定 TP2，进入逐 K 管理

TP1 成交后立即重新调用监督智能体，可选择

- 保持原止损
- 移到保本位
- 移到最新结构低点或高点
- 锁定部分利润
- 平掉剩余仓位
- 取消固定 TP2，进入逐 K 管理

执行层负责将比例换算为合法合约张数，并仅由 `ExecutionWorker` 调用现有 OKX 执行适配器创建、核验、修复或撤销保护。保护策略模块可以计算“需要什么保护”，但不得绕开 Worker 直接写券商。

## 9. 自动停止规则

### 9.1 连续完整止损

一次完整止损定义为

> 一个已完成生命周期的最终已确认净亏损（含已确认手续费、资金费和保守的未结算修正）达到该生命周期初始风险预算的 80% 或以上。

例如本轮风险预算为 1000 USDT

- 最终亏损 850，记一次完整止损
- 最终亏损 600，不记
- 最终盈利，不记

连续计数规则

- 完整止损，计数加 1
- 下一笔只要不是完整止损，无论小亏、保本或盈利，计数清零
- 连续三次完整止损后暂停新增仓位
- 将暂停原因、开始时间和 `pause_until_utc` 持久化到自动策略状态
- 到下一个 UTC 交易日后，只有完成新鲜对账、无未知请求/外部冲突、行情和模型健康、自动策略仍被用户启用时才解除暂停
- 已有仓位继续管理

### 9.2 历史最高净值回撤

- 以 PA 子账户资金调整后的历史最高净值为基准；每次计算均保存所用净值、资金流水水位和调整原因
- 回撤达到 50% 后，停止新增仓位
- 不在下一个交易日自动恢复
- 重启不能解除
- 必须由用户明确重新启用
- 已有仓位继续减险和退出

### 9.3 资金转入转出

目标能力中，PA 自动读取并逐页完整核对 OKX 资金流水，识别

- 主账户和子账户划转
- 充值
- 提现
- 其他资金调拨

转入不算交易盈利，转出不算交易亏损。资金流水接口的分页、时间、币种、账户范围和幂等键必须以已核验的 OKX 官方文档为准；任何一页获取失败、游标不连续或分类不明时，保留最后一个可信水位并停止自动修正历史高点/回撤，改为显式告警。

示例

```text
历史最高净值 12000
用户主动转出 5000
调整后的历史最高净值 7000
当前净值 7000
交易回撤 0%
```

## 10. 持续运行与恢复

### 10.1 Windows 启动

```text
Windows 启动
→ WinSW 启动 ExecutionWorker
→ ExecutionWorker 连接账户并对账本地账本、订单、成交、持仓和保护
→ 将运行中的券商影响命令标记为结果未知并优先对账，不盲目重发
→ WinSW 启动自动分析协调器；协调器只恢复持久化的策略状态，不恢复旧信号
→ 校验最近成功对账、账户身份、行情、模型、自动策略、暂停状态和仓位归属
→ 条件全部满足后，等待下一根新的已收盘 K 线再允许新风险
```

产品正式目标是不要求每次重启后重新输入逐笔确认文字，但重启绝不是自动放行。任一条件未知、过期、冲突或未通过时，只恢复监控、保护和退出，不恢复新增风险。

### 10.2 关闭 GUI

关闭窗口弹出三个选项

1. 仅关闭界面，后台继续自动交易
2. 停止自动交易并关闭
3. 取消关闭

默认选中「仅关闭界面，后台继续自动交易」，允许记住选择。

这是目标交互。当前 GUI 关闭会停止 GUI 内的持续跟踪分析；在自动分析协调器作为独立服务落地并通过恢复验收前，界面不得把“后台继续自动交易”显示为已可用。

### 10.3 恢复自动交易

暂停期间的旧信号只保存，不直接执行。

恢复时

1. 读取最新已收盘 15 分钟 K 线
2. 立即重新运行 PA 分析
3. 监督智能体重新审批
4. 使用最新净值和购买力计算仓位
5. 新信号仍成立才自动执行

## 11. 人工控制

主工作台不提供人工开新仓区域。

保留以下控制

### 暂停新开仓

点击后

- 禁止新开仓和加仓
- 先原子持久化暂停状态，再拒绝/撤销尚未送达 Worker 的新风险命令
- 由 Worker 取消 PA 尚未成交的入场挂单；部分成交时优先核验和维持/补齐保护，不得把已成交仓位置于无保护状态
- 正在进行的分析继续完成并保存
- 暂停期间信号标记为未执行
- 已有仓位继续管理
- 暂停状态持久化

### 紧急清仓

点击后

- 持久停止新增风险
- 只由 Worker 接收持久化紧急命令，先停止并取消未成交入场挂单
- 对 PA 已确认管理的仓位提交退出并持续对账；不得触碰外部、疑似或归属冲突仓位
- 在确认仓位归零前保留有效保护；确认归零后才撤销剩余 PA 保护单
- 退出结果未知时进入对账而不是盲目重复平仓；确认完成后进入持久停机
- 重启后不自动恢复
- 不操作外部仓位

### 其他允许操作

- 手动触发一次重新分析
- 查看并复制脱敏诊断
- 打开交易、智能体和执行详情

## 12. 仓位归属

一笔仓位只有同时满足以下条件，才能标记为 PA 管理仓位

1. 本地存在对应的 PA execution
2. 账户身份一致
3. 品种一致
4. PA 客户订单号和券商订单号可以对应
5. PA 成交链计算的剩余数量与实际仓位一致
6. 生命周期锁、账户、保证金模式和当前统一保护均与本地记录一致

其他情况分类为

- 外部仓位
- PA 来源疑似但本地链路不完整
- 仓位归属冲突

处理原则

- 不自动接管
- 不自动平仓
- 不自动补保护
- 阻止相同账户和品种新增风险
- 在界面清楚显示原因

## 16. 产品验收

第一阶段通过标准（其中“自动”项均为目标能力，必须以真实后端状态和验收记录证明，不能以设计稿代替）

- 选择 OKX 行情和 XAU-USDT-SWAP 后，主界面正确显示 15 分钟 K 线
- 同一根已收盘 K 线不会触发两次分析
- PA 与监督智能体分别使用独立模型档案
- 监督智能体所有写动作通过 PA 执行层
- 新开仓、加仓和反手都使用最新净值重新计算
- 动态杠杆和最大可开张数来自实际 OKX 账户
- 加仓后只有一套统一保护
- 反手前旧仓必须归零
- TP1 成交后能重新调用监督智能体
- GUI 关闭后，独立自动分析协调器仍能管理已有仓位并只处理新的已收盘 K 线
- Windows 重启后仅在恢复门禁全部通过时恢复自动循环，绝不重放旧信号或未知券商请求
- 暂停新开仓会取消未成交入场单
- 恢复后不执行旧信号，而是立即重新分析
- 紧急清仓只操作 PA 已确认仓位
- 外部仓位不会被接管
- 连续三次完整止损按定义自动暂停
- 资金划转不会被误算成盈亏
- 回撤 50% 后持久停止新增风险
- 主工作台 1920 × 1080 下无需纵向滚动即可看清核心状态
- 页面中不存在人工开新仓入口
- 除 `ExecutionWorker` 外，任何进程、模块或 UI 均无法获得券商写权限；并发命令、重启恢复、暂停和紧急清仓下均能证明这一点
- 执行账本保留逐笔执行事实，新增生命周期记录只做聚合和关联，不复制或篡改历史执行事实
