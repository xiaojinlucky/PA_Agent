## 3. 产品目标与边界

一句话目标：让用户在一个原生桌面页面内快速扫描四个市场的本地自选，并在启动两阶段价格行为分析前核对市场、报价和最新已收盘 K 线证据。

主流程：

1. 选择 `US / HK / CN / Crypto`。
2. 扫描当前市场的本地自选。
3. 选择标的与周期。
4. 核对市场时钟、报价新鲜度、最新已收盘 K 线和数据来源。
5. 证据满足门禁时开始两阶段分析；否则显示真实原因并禁用主动作。

本页允许的写入仅限本地设置：添加、删除、排序本地自选，保存当前页面选择。行情、名称、涨跌、市场时钟、认证状态和分析结果不写入设置。

本页禁止：

- 买入、卖出、下单、撤单、持仓、账户、资产、盈亏、杠杆、风险预算、自动交易、订单和券商写接口。
- 调用长桥云端 watchlist 写接口。
- 因失败静默换源、猜市场、沿用另一标的数值或用旧错误覆盖新页面。
- 让本页只读分析完成后自动创建执行计划。

## 4. 首屏信息架构

### 4.1 1440×900 目标预算

`1440×900` 指 `MainWindow.size()` 的完整 Qt 客户区，不包含操作系统窗口边框。方向 1 替换现有“分析工作台”一级页签的内容，不新增第三个一级页签；菜单栏、一级页签栏和状态栏属于应用壳层，不计入下述六个页面对象，但必须计入总高度。

| 区域 | 预算 | 内容 |
| --- | ---: | --- |
| 菜单栏 | `28px` 高 | 沿用应用壳层 |
| 一级页签栏 | `32px` 高 | 沿用“分析工作台 / 实盘交易”导航；本页挂在“分析工作台”内 |
| 页面顶部 | `48px` 高 | 唯一标题、四市场切换、当前数据来源、全局更新时间 |
| 左栏 | 约 `240px` 宽 | 当前市场本地自选、添加、删除、排序和单行行情状态 |
| 中央 | 约 `860px` 宽 | 当前标的、周期、最新已收盘 K 线、主图、两阶段分析状态与主动作 |
| 右栏 | 约 `340px` 宽 | 市场、行情、K 线、分析四组独立证据 |
| 页面主体 | `768px` 高 | 固定三栏；只允许自选、图表、分析结果和右栏内部按需滚动 |
| 状态栏 | `24px` 高 | 只显示本页全局状态；本页激活时隐藏执行、账户和交易字段 |

高度合计为 `28 + 32 + 48 + 768 + 24 = 900px`，三栏宽度合计为 `240 + 860 + 340 = 1440px`。页面三栏的外边距为零，边框与分隔线计入各列预算，不增加横向滚动。生产 QSS 必须冻结三段壳层高度；离屏测试同时断言 `MainWindow.size()`、页面 `contentsRect()`、裁切和滚动行为，不能只截页面净视口冒充整窗通过。

### 4.2 1920×1080 扩展

- 左栏保持约 `240px`，右栏最多扩至 `360px`。
- 增量宽度优先给中央图表和分析区，不增加新的顶层对象。
- 菜单栏、一级页签栏、页面顶部和状态栏保持 `28 / 32 / 48 / 24px`，页面主体增至 `948px`。
- 增量高度优先给图表和分析结果，不缩小或隐藏证据字段。
- 不能把 1920×1080 专属内容塞回 1440×900，导致小字或横向滚动。

## 6. 数据合同

### 6.1 路由

- `US / HK / CN` 只使用 Longbridge。
- `Crypto` 只使用 OKX。
- US、HK、CN 切换不得重复创建 Longbridge 数据源。
- Longbridge 与 OKX 跨源切换使用“先建立并验证新状态、一次提交、最后释放旧状态”的事务边界。
- 任何失败都不得静默换源。

### 6.2 QuoteSnapshot

`QuoteSnapshot` 的字段、类型、数值格式、完整性和身份不变量完整继承 `docs/prd/05_多市场看盘前端设计包.md` 第 2.4 节，不在本文删减或改写。至少包含：

`schema_version`、`selection_generation`、`request_sequence`、`symbol`、`market`、`source`、`name`、`currency`、`last`、`prev_close`、`change`、`change_pct`、`price_tick`、`quote_ts_utc_ms`、`received_at_utc_ms`、`quote_mode`、`expected_delay_ms`。

`symbol + market + source + selection_generation + request_sequence` 必须完整匹配请求身份；任一不一致就丢弃整份结果。名称、币种或涨跌字段缺失时逐项显示未知，不能使用旧标的、市场默认值或另一来源补齐。

### 6.3 新鲜度与日历

- 报价新鲜度、K 线新鲜度和市场日历分别判断。
- 报价状态为 `fresh / session_paused / stale / unavailable`。
- 认证失效立即清空报价，不保留旧数值。
- 同身份临时网络失败可保留最后权威快照及原时间，但必须显示“行情已过期”并禁用分析。
- 日历失败只让市场时钟显示“状态未知”；完整且新鲜的已收盘 K 线仍可用于只读分析。

### 6.4 本地设置

只扩展现有 `GeneralSettings / config/settings.json`，不新增第二份设置真值：

- `market_workspace_schema_version`
- `last_market`
- `last_symbols_by_market`
- `local_watchlists_by_market`

四市场列表只保存规范化代码；不保存名称、报价、涨跌、市场时钟、认证状态或分析结果。旧设置迁移、revision 冲突、重新载入、再次保存和迟到保存语义完整继承设计包。

每个窗口另维护不持久化、只增不减的 `settings_change_sequence`。添加、删除、排序自选或修改任何待保存页面选择时递增；保存任务携带不可变的完整设置快照、`selection_generation`、`settings_change_sequence` 和磁盘 revision。只有三者仍匹配最新待保存状态时才可清除“未保存”；同一 generation 内较旧的自选保存迟到成功也必须丢弃其界面完成信号，并继续排队最新完整快照。

### 6.5 高密自选行情集合

当前 `DataSource.subscribe(symbol, timeframe)` 只有单标的订阅，不能用它循环冒充最多 100 个自选行的行情能力。生产实现必须新增独立只读 `WatchlistQuoteSet`，与当前选中标的的 K 线订阅分开：

1. 集合以 `market + source + symbol` 为唯一键；每行值仍是完整 `QuoteSnapshot`，不得另造字段缩水的第二套报价真值。
2. 集合回调携带当前 `selection_generation`、`watchlist_change_sequence`、`watchlist_refresh_sequence` 和逐标的 `request_sequence`。增删排序递增 `watchlist_change_sequence`；每个刷新周期递增 `watchlist_refresh_sequence`；每个标的的请求序号独立递增。
3. 只有完整身份和四个序号都匹配当前状态的行可以更新。旧行成功、旧行失败、已删除标的和旧市场结果全部丢弃，不能显示错误、恢复旧值或改变当前选中标的。
4. Longbridge 与 OKX 适配器必须使用各自已核实的官方只读批量报价能力或明确有界的只读快照能力；实现前先核对当前 SDK/API 文档与额度。分块大小来自已核实的提供方限制，不能猜默认值。
5. 同一来源同时最多一个自选刷新周期在途；新周期开始时取消可取消的旧周期，不可取消的旧结果按序号丢弃。禁止为 100 个自选创建 100 个订阅、无界线程或无界并发请求。
6. 适配器未能证明安全批量/限流合同、认证失效或整批传输失败时，对应行显示“行情不可用”；已取得的同身份权威快照只按第 6.3 节的新鲜度规则保留，不能静默换源。

## 7. generation、请求序号与回滚

1. 页面维护只增不减的 `selection_generation`。
2. 每次提交新的市场、标的或周期组合时 generation 加一；同一选择的刷新不增加 generation。
3. 当前标的报价、K 线和静态信息三个请求族分别维护只增的 `request_sequence`；自选集合另按第 6.5 节维护集合与逐标的序号。
4. 所有连接、静态信息、报价、K 线、订阅、设置保存和分析回调携带发起时的 generation 与完整 `market + source + symbol + timeframe`；设置保存还携带 `settings_change_sequence`。
5. 报价、K 线和静态信息还必须校验本请求族的最新 sequence。
6. 旧 generation、旧 sequence 或身份不一致的成功与失败都直接丢弃，不能更新页面、缓存或设置，不能清除新状态，也不能显示旧错误。
7. 新状态只有在连接、标的、周期、首份报价和首份已收盘 K 线全部验证通过后一次性提交。
8. 普通连接、传输、标的或数据验证失败时，只有旧状态仍能被证明有效才保留并显示真实错误；旧状态恢复也失败时清空无法证明的数值并进入切换失败。
9. 分析启动时冻结 generation、市场、来源、标的、周期和最新已收盘 K 线；完成结果永远归属冻结身份。
10. Longbridge 全局认证失效优先于普通回滚：立即使 US/HK/CN 的当前与暂存报价全部无效，清空三市场数值并禁用分析，取消其待提交状态；不得回滚到同一失效认证下的旧 Longbridge 页面。独立验证的 OKX Crypto 状态不受影响。
11. 设置按 `selection_generation + settings_change_sequence + revision` 串行保存；任一较旧的保存迟到成功都不能把最新草稿标成已保存。

## 8. 状态与交互

必须覆盖：

- 初次加载、空自选。
- 市场切换中、切换失败。
- 行情不可用、认证失效、行情已过期。
- 日历未知、午休、闭市、半日市、连续交易。
- 设置未保存、设置已被其他窗口修改。
- 分析未开始、准备中、分析中、已完成、失败、已取消。

交互规则：

- 切换市场、标的或周期时，旧已提交页面保持可辨认；新状态不能提前显示成功。
- 删除本地自选不删除历史分析记录。
- 刷新只更新当前 generation 和对应请求族的最新 sequence。
- 开始分析前冻结完整身份；分析中切换时，用户先取消或等待当前任务。
- 设置保存失败保留已验证会话状态并显示未保存；重新载入明确放弃未保存草稿。
- 本页必须使用独立的“只分析”完成路径：可以复用纯两阶段分析计算和 `AnalysisRecord`，但不能进入现有会调用 `_prepare_execution_from_record()` 的主窗口完成处理器，也不能调用 `execution_service.prepare_analysis()`。即使全局 execution 已启用，本页完成一次分析也必须产生 0 个 execution、0 条 Worker 写命令和 0 次券商写调用。

## 10. 外部设计与实现门

顺序固定为：

1. 本文锁定现有 ImageGen 候选稿的用户偏好与本地事实。
2. 补齐 Product Design `ideate` 的可核验入口、提示词与三方向产物绑定；若旧证据无法恢复，重新生成三张独立方向并让用户按新一轮实际显示顺序重新选择，不能把当前编号自动套到新产物。
3. 网页版 ChatGPT 输出完整 PRD，并保存会话 URL、完整提示词、逐文件附件、完整回答和本地事实校正。
4. 使用本机已登录 Chrome 在 Stitch 生成方向绑定设计，并保存真实项目、页面、Screen/版本、输入、附件、结果和本地适配差异。
5. ImageGen R1 结构轮：精确 `1440×900`，修正标题、越界文案、状态只靠颜色和本地自选语义。
6. ImageGen R2 视觉轮：实际调用项目级 `design-taste-frontend` 作本轮指导，修正字号、对比度、留白、边框、数字对齐和比例。
7. ImageGen R3 状态轮：覆盖加载、空、认证失败、陈旧、日历未知、切换失败、保存冲突和分析状态。
8. 三轮完成后再次独立执行 `design-taste-frontend` 生产视觉审计，记录采用、调整和拒绝的参考；R2 的过程指导不能替代该终审。
9. 用户再次确认最终精修稿。
10. 只有范围授权与全部设计门均通过后，才允许写 PyQt6 生产代码。

三轮必须连续以前一轮真实输出为下一轮输入；三张旧候选稿不能算三轮精修。

## 12. 当前代码映射与范围冲突

当前代码没有可直接拼装的多市场页面：现有主窗口仍以数据源和标的下拉框为主；没有按市场本地自选、`QuoteSnapshot` 页面读模型或市场时钟；现有刷新回调也没有完整身份与 generation。

可复用基座仅限：

- `ChartWidget` 的原生绘图能力；
- 两阶段分析链中的纯分析计算与 `AnalysisRecord`，不复用会准备 execution 的完成处理器；
- `market_calendar.session_state` 只用于 US/HK/CN，Crypto 使用连续市场规则；
- 设置 revision 机制和 Longbridge/OKX 只读适配器中的已验证能力。

现有 `_switch_data_source()` 只能参考“先准备、后提交、再释放”的事务意图，不能直接复用实现：它在首份报价和 K 线验证前已经替换活动数据源，且连接、验证和订阅会阻塞界面线程。生产实现必须新增由工作线程拥有的异步暂存状态；暂存状态完成连接、静态信息、订阅、首份报价和首份已收盘 K 线后，主线程只提交一次不可变页面快照，最后释放旧状态。取消或失败只释放暂存资源，不得写页面、缓存或设置。

真正落地必然需要修改 `pa_agent/gui`。用户原始范围明确禁止触碰该目录，因此“选择方向 1”只完成审美方向门，不自动解除生产代码禁区。外部设计门全部完成后，仍需用户明确解除 `pa_agent/gui` 禁区，才能进入实现。
