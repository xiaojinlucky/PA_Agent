# PA_Agent 交给 Google Stitch 的最终设计提示词（目标架构版）

你是一名资深桌面端量化交易产品设计负责人。请为 PA_Agent 设计 Windows PyQt6 桌面端高保真界面。

本任务只负责前端设计稿，不生成代码，不改变业务规则，不虚构后端能力。

## 使用前提与事实边界

这是**目标架构设计稿**：它要表达已经冻结的产品方向，但不能把目标能力误画成当前仓库已经可操作的实盘能力。设计前应先读取并遵守以下输入，优先级从高到低：

1. `01_PA_Agent_产品PRD.md`：产品规则、风险和恢复契约。
2. `03_PA_Agent_工程移交与硬验收.md`：进程边界、状态机、现有能力与待建设能力。
3. 当前程序的关键页面截图与“页面—字段—状态—交互”映射：主窗口、AI 侧栏、交易对话框、图表、执行状态。

当前已验证的基础是 OKX 公共 K 线、PA 分析、`ExecutionController`、独立 `ExecutionWorker`、执行账本、订单保护和对账。当前还**不是**已完成的无人值守自动交易系统：GUI 关闭会停止 GUI 内的持续分析；固定数量计划、单个全局活动模型档案、短期新风险授权和部分人工确认仍是现状；加仓、反手、动态杠杆、自动停止、完整生命周期和持久自动循环均属于目标能力。

因此每个组件都必须能表达三种可用性：

- **已确认**：已由 Worker 对账确认的行情、订单、成交、仓位、保护或系统健康事实。
- **计划/建议**：智能体建议、风险批准计划、等待 Worker 执行的命令；绝不能画成已成交或已持仓。
- **规划中/不可用**：目标能力尚未有后端状态、权限和验收时的展示方式。用灰色说明与禁用态，不能做成可点击的真实交易按钮。

本提示词中的“自动策略”“加仓”“反手”“紧急清仓”等状态稿均为目标状态参考，除非后端状态映射已经交付，否则不得被解释为当前程序可用。

## 一、产品定位

PA_Agent 是 AI 驱动的价格行为自动交易控制台。

它不是传统券商软件，也不是单纯的聊天式 AI 工具。核心链路是

> OKX 行情 → PA 价格行为分析 → 交易监督智能体 → 风险和仓位计算 → 自动分析协调器创建命令 → ExecutionWorker 唯一写入券商 → 持仓管理 → 复盘

目标首版只打通

- OKX
- XAU-USDT-SWAP
- 15 分钟周期
- 单品种
- 单策略
- PA 专用 OKX 子账户
- 全仓
- 净持仓
- USDT 资金池
- 自动做多与做空

后续会扩展到多品种、多策略、多账户，因此布局要可扩展，但首版不要提前堆满复杂组合功能。不得把多品种、组合风险、人工开仓或外部仓位接管画入首版。

始终显示

### 4. 当前执行


用一条紧凑执行链显示：等待信号、正在计算、命令已入队、入场等待成交、正在建立保护、持仓正常、正在加仓、正在减仓、正在平仓、正在反手、状态未知正在对账。

“命令已入队”“已提交”“部分成交”“已确认保护”是不同状态；未知状态必须保留最近已确认事实，并明确禁止重复提交。加仓、减仓、反手和自动保护调整在未落地时显示“目标状态”，不能与当前 Worker 已实现的提交/取消入场/请求离场/对账混淆。

显示最关键的订单号安全摘要、数量、均价和保护状态。

### 5. 下一步

用一句明确中文告诉用户系统接下来会做什么，例如

- 等待下一根 15 分钟 K 线收盘
- 等待入场单成交
- TP1 成交后将调用监督智能体
- 正在确认旧仓已归零，再准备反手
- 暂停期间继续分析，但不执行新信号

下一步必须同时给出前置条件和数据时间。例如“等待下一根已收盘 15 分钟 K 线（行情：12:45 UTC，执行对账：12:44 UTC）”，不能在订单结果未知时写成确定会开仓。

## 十一、主要状态设计

### 共同规则

每张状态稿都要显示：自动策略状态、交易执行后台状态、行情时间、最近成功对账时间、当前能力级别（已确认 / 计划 / 规划中）。不要让“自动策略运行中”替代 Worker 健康，也不要让“模型已给建议”替代订单已提交。

### 空仓运行

- 自动策略状态按能力映射显示；当前未启用自动协调器时显示“当前仅人工确认执行”
- 正在等待 K 线
- 右侧显示最近一次 PA 观点
- 当前执行显示无活动交易

### 分析中

- 顶部显示 PA 正在分析
- K 线图冻结在本轮已收盘快照
- 右侧显示进度
- 不使用大面积加载遮罩

### 信号未执行

明确显示原因

- 监督智能体拒绝
- 暂停新开仓
- 连续完整止损暂停
- 回撤停止
- 外部仓位
- 账户或品种不一致
- 购买力不足
- 模型失败采用确定性兜底
- 快照过期、合约规格无法验证或动态能力尚未启用

### 外部仓位

使用醒目的非 PA 标识

- 外部仓位，不由 PA 管理
- PA 不会平仓、加仓或补保护
- 相同账户和品种停止新增风险

不要提供接管按钮。

### 请求结果未知

- 不能显示成失败或成功
- 显示正在按客户订单号和券商订单号对账
- 禁止重复提交
- 保留最近确定状态

### 暂停新开仓

- 先显示“暂停策略已持久化”，再显示 Worker 取消尚未成交的 PA 入场单
- 继续显示 PA 分析
- 已有仓位继续管理
- 明确标记暂停期间信号未执行
- 如果暂停/取消命令还未由 Worker 对账确认，显示处理中而不是“已取消”

### 紧急清仓

二次确认内容必须明确

- 取消 PA 入场挂单
- 平掉 PA 管理仓位
- 在确认仓位归零前保留有效保护，确认归零后才撤销剩余 PA 保护单
- 不操作外部仓位
- 完成后保持停止，不自动恢复

紧急清仓必须是目标能力的二次确认稿；未有对应 Worker 命令、归属核验和对账闭环时，只展示禁用的“规划中”控制位。

## 十二、视觉规范

### 颜色方向

- 页面背景，低饱和深灰黑
