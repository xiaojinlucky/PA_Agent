## 1. 交付任务

请为 PA_Agent 设计一个原生桌面端“多市场看盘与两阶段分析”主页面。

必须交付：

1. 一张精确 1440×900 的正常状态高保真主页面。
2. 同一页面的 8 个状态变体：加载、空数据、行情过期、认证失败、日历未知、
   切换失败、分析进行中、分析失败。
3. 一张 1920×1080 自适应布局图。
4. 组件状态表：默认、悬停、选中、禁用、加载、失败。
5. PyQt6 组件映射表，说明每个视觉区域应落成什么 QWidget、布局和
   pyqtgraph 组件。
6. 所有颜色、字号、间距、圆角、边框和控件尺寸的令牌表。

禁止交付：

1. 不做移动端。
2. 不做网页、HTML、React、WebView 或 JavaScript 版本。
3. 不加入买入、卖出、下单、撤单、仓位、账户、资产、杠杆或自动交易控件。
4. 不复制长桥品牌、Logo、专有图标、原文、私有资产或精确页面。
5. 不用小于 14px 的文字，不用副标题、眉题、营销口号、灰色辅助小字或小号页脚。
6. 不把效果图中虚构的数据、按钮或指标当成后端已经提供的能力。

## 2. 产品定义

### 2.1 主问题

当前选择的市场和标的是否有可信、足够新鲜的数据，可以开始一次只读的
价格行为分析？

### 2.2 主对象

一个完整且不可混用的选择身份：

`市场 + 数据源 + 标的 + 展示周期 + selection_generation`

其中：

- 市场：`US`、`HK`、`CN`、`Crypto`。
- 数据源：US/HK/CN 固定为 Longbridge；Crypto 固定为 OKX。
- 展示周期：`10m`、`1h`、`4h`。
- 分析周期：首版固定为 `10m`，不随展示周期改变。
- `selection_generation` 是每次选择变化后的唯一版本号，用来丢弃迟到结果。

### 2.3 主动作

`开始分析`

只有当前 10m 已收盘 K 线达到门槛、报价和 K 线身份一致、数据没有被硬阻断，
且行情源提供可追溯的真实最小跳动时才可点击。页面不是交易终端，分析完成也
不能触发交易准备或下单。

### 2.4 使用者

首版面向 Owner/研究者本人，是高信息密度桌面工作站。普通用户和付费分层
不是本轮设计范围。

## 3. 设计方向

采用“长桥式专业工作站的结构语言 + PA_Agent 的证据优先逻辑”：

1. 左侧用于快速扫描当前市场自选。
2. 中央用于当前标的、K 线和分析结果。
3. 右侧用于报价、市场时钟、数据证据和分析门禁。
4. 数据风险必须比装饰更醒目。
5. 页面稳定、克制、紧凑，不使用大卡片堆叠或营销型仪表盘。

可吸收的公开结构原则：

- 固定外壳、紧凑标签、低对比边界。
- 左侧列表、中央主工作区、右侧详情栏。
- 表格数字等宽对齐，选中行驱动中间和右侧同步变化。
- 红涨绿跌；行情色与系统健康色分开。

不得吸收：

- 长桥品牌、订单面板、账户面板、券商交易外观和精确图标。
- 页面中的任何下单或资金功能。
- 受版权保护的完整页面复刻。

## 5. 页面结构

### 5.1 菜单栏

只保留原生桌面菜单：

`文件`、`视图`、`设置`、`帮助`

### 5.2 一级工作区标签

首版只需要：

`多市场看盘`、`分析记录`

当前标签使用蓝色底边和较高文字对比，不用大面积亮色填充。

### 5.3 页面上下文栏

从左到右：

1. 页面标题：`多市场看盘`
2. 四市场切换：`美股`、`港股`、`A股`、`加密`
3. 当前数据源：`Longbridge` 或 `OKX`
4. 全局连接状态：图标 + `可用`、`恢复中`、`认证失效` 或 `不可用`
5. 最右侧刷新按钮。

市场和来源是一一绑定的，不允许做成两个可自由组合的下拉框。

### 5.4 左侧自选

顶部：

- 当前市场名称。
- 搜索框。
- 本地添加按钮。

表头：

`标的`、`最新价`、`涨跌幅`

每行固定 40px，单行显示：

- 左侧：代码，14px。
- 中间：最新价，等宽字体，14px。
- 右侧：带正负号的涨跌幅，等宽字体，14px。

交互：

- 单击选中并开始暂存新选择。
- 新选择的首份报价和 K 线通过后，中央与右侧一次性切换。
- 切换过程中旧页面保持可用，但顶部明确显示 `正在切换到 …`。
- 失败时旧页面不被新标的的局部数据污染。
- 添加、删除、排序只修改本地自选，不调用云端自选接口。
- 每个市场最多 100 项。

### 5.5 中央标的与报价摘要

左侧：

- 标的代码，22px。
- 正式名称，14px；名称没有可靠来源时只显示代码，不猜名称。
- 市场和来源状态徽标。

中间：

- 最新价，22px 等宽。
- 涨跌额与涨跌幅，14px 等宽，必须有正负号。
- 行情源时间，14px。

右侧：

- 展示周期：`10m`、`1h`、`4h`。
- `开始分析` 主按钮。

报价不属于任何 K 线周期。切换展示周期不能重新定义报价，也不能改变固定
10m 分析周期。

### 5.6 K 线主图

复用 pyqtgraph 的原生 K 线画布：

- 深色背景。
- 红色阳线、绿色阴线。
- 价格轴在右侧，时间轴在底部。
- 仅显示当前展示周期。
- 图表顶部只保留必要的 OHLC、时间和数据状态。
- 未收盘 K 线必须与已收盘 K 线有明确样式差异。
- 任何迟到的旧 generation 图表结果都不能闪现。

图表不加入装饰粒子、扫描线、霓虹动画或面积渐变。

### 5.7 两阶段分析结果

固定分成左右两栏：

左栏 `市场诊断`：

- 周期位置。
- 方向。
- 市场判断置信度。
- 高周期背景状态：10m、1h、4h 各自显示 `就绪`、`不足`、`过期` 或
  `不可用`。

右栏 `决策摘要`：

- 订单类型字段可以显示模型结论，例如 `不下单`、`限价单`、`突破单`；
  这里只是分析结论，不能出现提交订单按钮。
- 方向。
- 交易置信度。
- 入场、止损、目标。
- 终局：`trade`、`wait` 或 `reject` 的中文显示。
- 理由正文。

分析失败时整块显示明确失败类别和阶段，不保留上一标的结果冒充当前结果。

### 5.8 右侧即时报价

字段：

- 最新价。
- 上一收盘价；源不提供时显示 `—`。
- 涨跌额。
- 涨跌幅。
- 币种；源不提供时显示 `—`。
- 行情源时间。
- 本机接收时间。
- 行情模式：`实时` 或 `延迟`。
- 新鲜度：`新鲜`、`休市保留`、`已过期`、`不可用`。

不允许：

- 用 24 小时开盘价冒充上一交易日收盘价。
- 用刷新失败时间冒充行情时间。
- 从价格小数位猜最小跳动。

### 5.9 右侧市场时钟

股票市场显示：

- `开市`、`午休`、`闭市`、`半日市` 或 `状态未知`。
- 交易所当地时间。
- 下一状态变化时间。
- 明确的时区名称。

加密市场显示：

- `连续交易`
- `UTC`

加密市场不能出现午休、半日市或股票闭市语义。

### 5.10 右侧 K 线证据

用三行显示 10m、1h、4h，每行包含：

- 周期。
- 已收盘根数 / 要求根数。
- 最新已收盘 K 线时间。
- 状态图标 + 状态文字。

完整状态：

- `就绪`：数量满足，时间和身份有效。
- `不足`：已收盘根数不够。
- `已过期`：身份正确但时间超过门槛。
- `不可用`：认证、权限、标的不支持、字段无效或无数据。

10m 是分析硬输入。1h/4h 是高周期背景；缺少时页面必须如实显示，不得
生成虚构背景。

### 5.11 右侧分析门禁

只显示一个主结论：

- `可以开始分析`
- `等待 10m 数据`
- `行情已过期`
- `认证失效`
- `标的不受支持`
- `数据身份不一致`
- `分析进行中`
- `分析失败`
- `仅展示，价格分析不可用`

下面列最多 3 个具体阻断原因，字号仍为 14px。主按钮只在可分析时启用。

### 5.12 底部状态栏

从左到右：

- 当前市场 / 标的 / 展示周期。
- 当前 generation。
- 最近一次成功刷新时间。
- 本地设置：`已保存` 或 `未保存`。

底部信息是操作和审计所需状态，不是装饰性页脚。

## 7. 后端已经提供的合同

设计和生产实现都不得假设这些合同之外的能力。

本节表示“无界面合同与数据适配已经存在”，不表示现有 `pa_agent/gui` 已经接线。
生产实现必须通过唯一 Controller 把这些对象接入 Qt signal/slot 和页面组件。

### 7.1 已实现

1. `SelectionIdentity`
   - `selection_generation`
   - `market`
   - `source`
   - `symbol`
   - `display_timeframe`
   - 固定 `analysis_timeframe="10m"`

2. `RequestToken`
   - 完整选择身份。
   - 请求族：连接、静态资料、报价、K 线、自选、设置、分析。
   - 每个请求族独立递增的 `request_sequence`。

3. `QuoteSnapshot`
   - 标的、市场、来源、名称、币种。
   - 最新价、上一收盘价、涨跌额、涨跌幅。
   - 行情源时间、本机接收时间。
   - 实时/延迟模式及预期延迟。
   - 行情源声明的最小跳动可以为空；为空时页面仍可展示，但必须在调用 AI 前
     阻断价格分析并显示 `仅展示，价格分析不可用`，不能用猜测值补齐。

4. `QuoteFreshnessView`
   - `fresh`
   - `session_paused`
   - `stale`
   - `unavailable`

5. `WatchlistRequestToken`、`WatchlistGenerationGate`、`WatchlistQuoteSet`
   - 最多 100 项。
   - 自选列表有独立的 change sequence 和 refresh sequence，不受当前单一标的限制。
   - 只接受最新 generation、最新刷新批次和完整标的集合。
   - 任一标的缺报价时整批失败，不静默保留旧行。

6. `KlineEvidenceView`
   - 周期、总根数、已收盘根数、要求根数。
   - 最新已收盘时间、本机接收时间、统一 `analysis_as_of_utc_ms`、最小跳动。
   - 根据根数、最新收盘时间、本机时间、最大年龄和休市状态自行计算
     `ready`、`insufficient`、`stale`、`unavailable`，调用方不能直接伪造 READY。

7. `MarketDataBundle`
   - 一份报价、10m、可缺失的 1h/4h 共用同一标的、来源、generation、
     K 线请求序号和 `analysis_as_of_utc_ms`。
   - 10m 是硬输入；1h/4h 缺失、过期或不可用时不得阻断合格的 10m，
     也不得生成未被证据证明的高周期方向文字。
   - 无权威 `price_tick` 时状态为 `display_only`，不得调用两阶段 AI。

8. `SelectionGenerationGate`
   - 新选择先暂存，验证后一次性提交。
   - 失败时放弃暂存并保留旧提交。
   - 旧 generation 和旧请求序号的成功、失败都被丢弃。

9. `AnalysisResultView`
   - 把两阶段分析记录投影为纯只读页面结果。
   - 绑定 generation、请求序号、市场、来源、标的和固定 10m 周期。
   - 投影前必须通过当前 generation/最新 analysis sequence、标的、来源和固定 10m
     身份校验。
   - 不进入 execution，不准备订单，不修改交易运行态；当前 GUI 尚待接线。

10. OKX 公共行情
   - SPOT/SWAP 按产品类型批量报价，不逐标的请求。
   - 10m 由真实 5m K 线聚合。
   - 支持最多三页历史读取，满足默认分析加 55 根指标预热。
   - 分页时间戳冲突或游标不前进会失败关闭。

11. Longbridge 只读行情
    - 同一 QuoteContext 串行调用。
    - 最多 100 个自选在一次 quote 调用中批量读取。
    - US/HK/CN 使用同一认证上下文。
    - 已过期或服务端 `401004` 会成为明确认证失败。
    - `realtime` / `delayed` 及延迟毫秒只由同一服务端连接的
      `quote_level()` 与 `quote_package_details()` 证据推导；调用者无权声明或覆盖。
    - 套餐或行情级别未知、过期、矛盾，或权限读取失败时整批不可用，
      禁止默认标成实时；失败重连不得继续展示旧权限。
    - 套餐声称实时、但同市场行情级别只有延迟或低级别时必须失败关闭。
    - 实时和延迟权限证据最多缓存 5 分钟；到期后必须原子重读服务端，
      刷新失败不得沿用旧证据。
    - SDK 返回的无时区时间统一解释为宿主机当地墙钟时间，再转换为 UTC；
      报价与 K 线禁止采用两套解释。
    - 报价收到时间必须由数据源在 SDK 响应完成后盖章，调用者不得在请求前预填。
    - 供应商返回重复/额外 symbol，或分页同时间戳内容冲突时整批失败关闭。

### 7.2 当前真实能力边界

- 2026-07-29 已用同一个 `COMPREHENSIVE` 只读 QuoteContext 真实验收
  AAPL.US、700.HK、600519.SH 的报价及 10m/1h/4h K 线；三市场服务端权限
  均证明为实时。
- Longbridge quote/static_info 当前没有给出可追溯的统一最小跳动，因此三类股票
  在 v0.1.0 中是 `display_only`：可以看盘，不得启动价格分析。
- 认证失败态仍必须保留；凭据失效时不得静默换源、绕过或复用其他凭据。
- 真实验收只证明只读行情和时间合同，不证明 Longbridge 交易能力；Longbridge
  paper/交易长期排除。

## 8. 异步与切换规则

### 8.1 同一数据源内切换

1. 用户选择新标的后生成新的 generation。
2. 旧提交页面继续显示。
3. 新标的静态信息、报价和首份 K 线在暂存区加载。
4. 身份、周期、完整性都通过后一次性提交。
5. 任一步失败就放弃暂存，旧页面保持不变并显示新目标的错误。
6. 旧回调迟到时完全丢弃，不能显示错误、清空新页面或写设置。

### 8.2 Longbridge 与 OKX 跨源切换

1. 新数据源先建立和验证，旧数据源保持运行。
2. 新源完整就绪后才提交。
3. 提交成功后再释放旧源。
4. 释放失败只记资源错误，不回滚已经验证的新页面。
5. 旧刷新线程不能继续向页面发回调。

### 8.3 设置保存

1. 切换成功与设置落盘是两个状态。
2. 保存失败不回滚当前已验证页面，显示 `未保存`。
3. 只允许最新 generation 的完整设置快照成为 `已保存`。
4. 旧保存晚到不能覆盖新选择。

### 8.4 分析

1. 提交分析时冻结完整 identity、10m K 线和 1h/4h 背景。
2. 分析结果必须通过原请求 token 回到页面。
3. 用户已经切换时，旧分析可进入历史，但不能覆盖当前标的。
4. 页面分析完成路径不能调用交易准备、订单预检或 execution service。

## 9. 状态设计

### 9.1 加载

- 保留布局边界，使用静态骨架或明确进度。
- 不显示随机行情数字。
- 切换时旧数据保留，但加 `正在切换到 …` 状态条。

### 9.2 空数据

- 中央显示 `暂无行情数据`。
- 右侧证据显示各周期 `不可用`。
- 分析按钮禁用。

### 9.3 行情过期

- 同身份最后快照可以保留。
- 显示原行情时间和 `已过期`。
- 降低数值饱和度，不把旧值伪装成实时值。
- 分析按钮禁用。

### 9.4 认证失败

- US/HK/CN 报价数值立即清空。
- 显示 `Longbridge 认证失效`。
- 不展示原始异常、Token 或调用栈。
- Crypto 的独立 OKX 状态不被清空。

### 9.5 日历未知

- 市场时钟显示 `状态未知`。
- 报价仍按自己的时间判断。
- 日历未知本身不阻断完整、新鲜、已收盘 K 线的只读分析。

### 9.6 切换失败

- 新目标错误显示在上下文栏。
- 旧已提交页面保持完整。
- 如果旧状态也无法恢复，清空无法证明的数值并显示 `切换失败`。

### 9.7 分析进行中

- 分析按钮变为禁用的 `分析中`。
- 显示阶段：`市场诊断` 或 `决策生成`。
- 不遮挡 K 线和证据栏。

### 9.8 分析失败

- 显示失败阶段和稳定错误类别。
- 允许重新分析。
- 不保留上一标的结果冒充本轮结果。

视觉验收：

1. 1440×900 和 1920×1080 无截断、重叠和全页滚动。
2. 所有必要文字至少 14px。

6. 表格行固定 40px，不出现双行拥挤。

   文字、焦点环和图标不被裁切。
