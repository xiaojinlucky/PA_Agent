# 多市场看盘前端设计包

## 1. 本轮范围

本文件冻结多市场看盘页的页面合同，并提供三个可供用户选择的视觉方向。

本轮只交设计，不修改 PyQt6 代码。先用 Product Design 产出三套可见的高保真候选稿，用户看图选择后，才进入方向绑定的网页版 ChatGPT PRD、Stitch、三轮图像精修、视觉审计和生产实现。

设计真值按以下顺序使用：

1. `D:\Desktop\Quant\前端设计\DESIGN.md`
2. 当前 PA_Agent 数据合同与状态语义
3. `CONTEXT.md`、`lessons.md`、`docs/WORKORDER_MASTER_20260727.md`
4. 长桥参考素材中的工作站结构、密度、切换节奏和右侧详情栏

只吸收公开可辨认的结构规律，不复制品牌、原文、图标、精确坐标、订单面板或交易外观。

## 2. 页面合同

### 2.1 主问题

用户必须在五秒内看清：

1. 当前市场和标的是什么。
2. 市场现在处于什么阶段。
3. 行情和已收盘 K 线是否新鲜。
4. 当前可以查看、切换或开始哪项分析。

### 2.2 主对象与主动作

- 主对象：当前市场下的当前标的。
- 主动作：开始两阶段价格行为分析。
- 次动作：切换市场、切换标的、管理本地自选、刷新行情。
- 明确排除：买入、卖出、加仓、撤单、离场、券商路由、自动交易开关。

### 2.3 首屏对象预算

首屏只保留六个顶层对象：

1. 市场切换。
2. 当前标的与本地自选。
3. 市场时钟。
4. 行情新鲜度。
5. K 线与分析主区。
6. 右侧证据详情。

原始数据、连接诊断、完整日历信息和历史分析下沉到抽屉或详情页。

### 2.4 字段合同

| 区域 | 必须显示 | 数据来源 | 不可信时 |
| --- | --- | --- | --- |
| 市场切换 | 美股、港股、A股、加密 | 待新增的页面市场状态与市场路由表 | 保留原选择并显示无法切换 |
| 标的选择 | 代码、名称、所属市场 | 当前数据源符号列表；名称依赖待新增行情合同 | 不显示旧名称冒充新标的 |
| 本地自选 | 代码、名称、最新价、涨跌、更新时间 | 待新增的按市场本地自选结构与只读行情合同 | 单行显示已过期或读取失败 |
| 市场时钟 | 开市、午休、闭市、半日市、下一变化时间 | `market_calendar.session_state` | 显示状态未知，不猜下一时刻 |
| 加密时钟 | 连续交易、当前 UTC 时间 | 连续市场规则 | 不套用股票开盘和尾盘 |
| 行情摘要 | 最新价、涨跌额、涨跌幅、最新行情时间 | 待新增的只读 `QuoteSnapshot` 合同 | 按下文的可信度规则保留或清空 |
| K 线证据 | 周期、最新已收盘 K 线时间、根数、数据源 | `KlineFrame` | 阻止开始新分析并显示原因 |
| 分析状态 | 未开始、准备中、分析中、已完成、失败、已取消 | 现有两阶段分析状态 | 不把失败显示成等待 |
| 右侧详情 | 当前标的证据、市场状态、数据来源、最近分析摘要 | 只读模型与分析记录 | 逐项标记未知 |

涨跌默认采用红涨绿跌。涨跌值必须同时带正负号，不能只靠颜色。系统健康、警告和阻断使用独立颜色语义。

#### 现有读取路径与生产缺口

| 能力 | 当前真实状态 | 生产实现前的动作 |
| --- | --- | --- |
| 已收盘 K 线 | `KlineFrame` 已有标的、周期、OHLCV、开盘时间和收盘标记 | 可直接显示最新已收盘 K 线的收盘价、时间和根数 |
| 市场日历 | `market_calendar.session_state` 已有阶段、半日市和下一变化时间 | 只把它用于市场时钟和解释性标签 |
| 跨数据源切换 | `_switch_data_source(kind)` 已按数据源执行连接、验证与订阅事务 | 只用于数据源真的变化时，不冒充同一 Longbridge 内的市场切换 |
| 最近标的 | `last_symbols_by_source` 目前只按数据源保存 | 新增按 US、HK、CN、Crypto 分开的最近标的状态 |
| 本地自选 | 目前没有本页所需的按市场自选结构 | 在 `GeneralSettings` 新增按市场保存的自选结构后才能接线 |
| 实时行情摘要 | 通用 `DataSource` 不保证名称、最新价、涨跌和行情时间；Longbridge 的静态信息没有保留成页面读模型 | 先新增纯只读 `QuoteSnapshot`，至少含 symbol、market、name、last、change、change_pct、quote_ts、source 和 freshness |

`QuoteSnapshot` 和按市场设置结构完成前，页面只能把最新已收盘 K 线的收盘价与时间明确标成“K 线收盘”，不能冒充实时行情。

#### `QuoteSnapshot` 精确合同

`QuoteSnapshot` 是后续生产实现需要新增的不可变只读值对象，不是当前已经存在的代码。数值统一使用十进制定点字符串持久化或跨线程传递，禁止先转成二进制浮点数再显示。字段如下：

| 字段 | 类型 | 必填 | 语义与约束 |
| --- | --- | --- | --- |
| `schema_version` | `Literal[1]` | 是 | 当前合同版本，只能为 `1` |
| `selection_generation` | `int` | 是 | 创建本快照的页面选择代号，必须大于等于 `1` |
| `request_sequence` | `int` | 是 | 同一 selection generation 内只增不减的刷新请求序号，必须大于等于 `1` |
| `symbol` | `str` | 是 | 规范化标的；Longbridge 使用 `ticker.region`，OKX 使用现有标准化合约标识 |
| `market` | `US / HK / CN / Crypto` | 是 | 必须与标的后缀和页面目标市场一致 |
| `source` | `longbridge / okx` | 是 | US、HK、CN 只能为 `longbridge`；Crypto 只能为 `okx` |
| `name` | `str \| null` | 是 | 行情源返回的名称；没有权威名称时为 `null`，界面只显示代码 |
| `currency` | `str \| null` | 是 | 行情源声明的计价币种；未知时为 `null`，不得按市场猜测 |
| `last` | `DecimalString` | 是 | 最新权威价格，必须为正有限数值 |
| `prev_close` | `DecimalString \| null` | 是 | 前收盘价；行情源未返回时为 `null` |
| `change` | `DecimalString \| null` | 是 | `last - prev_close`；缺 `prev_close` 时必须与 `change_pct` 同时为 `null` |
| `change_pct` | `DecimalString \| null` | 是 | `change / prev_close × 100`，单位为百分点，不是比例小数 |
| `price_tick` | `DecimalString \| null` | 是 | 行情源声明的真实最小跳动；缺失时为 `null`，不得从显示小数位反推 |
| `quote_ts_utc_ms` | `int` | 是 | 行情内容对应的 UTC 毫秒时间 |
| `received_at_utc_ms` | `int` | 是 | PA_Agent 完整收到并校验本快照的 UTC 毫秒时间 |
| `quote_mode` | `real_time / delayed / unknown` | 是 | 只认行情源返回的权限或延迟属性；未知时不得显示“实时” |
| `expected_delay_ms` | `int \| null` | 是 | 只有行情源明确声明延迟窗口时才填写非负毫秒数；实时行情固定为 `0`，未知模式为 `null` |

`DecimalString` 是不使用科学计数法的十进制 JSON 字符串，格式为 `^-?(0|[1-9]\d*)(\.\d+)?$`；禁止 `NaN`、`Infinity`、逗号和单位字符。`last`、`prev_close` 与 `price_tick` 必须大于零，`change` 和 `change_pct` 允许为负数或零。

不变量：

1. `symbol + market + source + selection_generation + request_sequence` 五项必须与发起请求的完整身份一致；任一不一致都丢弃整份结果。
2. `last`、`prev_close`、`change`、`change_pct` 和 `price_tick` 必须是有限十进制数；要求为正的字段不接受零或负数。
3. 有 `prev_close` 时，`change` 和 `change_pct` 必须由行情读取层一次性计算并随快照发布；前端不得重复计算。无 `prev_close` 时两项同时为空。
4. `price_tick` 缺失不允许阻止只读显示原始价格，但前端不得自行补精度，也不得把该快照用于需要真实 tick 的价格校验。
5. `received_at_utc_ms` 由本机在完成校验后生成，不得晚于当前本机时间；`quote_ts_utc_ms` 不得晚于本机当前时间超过 `5,000 ms`。违反任一条件都按时钟异常拒绝，不把负年龄显示成新鲜行情。
6. 名称、币种或涨跌字段缺失时逐项显示未知；不得用旧标的字段、市场默认值或另一数据源结果补齐。
7. `QuoteSnapshot` 不写入 `GeneralSettings`，不成为第二套行情缓存真值。设置文件只保存用户选择和本地自选。

#### 新鲜度读模型

页面不直接给 `QuoteSnapshot` 加颜色，而由只读读模型发布以下状态：

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `generation` | `int` | 当前页面选择代号 |
| `request_sequence` | `int` | 当前 generation 已发出的最新刷新序号 |
| `requested_identity` | `market + source + symbol` | 当前请求身份 |
| `snapshot` | `QuoteSnapshot \| null` | 当前身份最后一份权威快照 |
| `freshness` | `fresh / session_paused / stale / unavailable` | 可见新鲜度 |
| `reason` | 稳定枚举 | `none / session_break / session_closed / age_exceeded / auth_failed / transport_failed / incomplete / identity_mismatch / source_mismatch / clock_invalid` |
| `failed_at_utc_ms` | `int \| null` | 最近一次读取失败时间，不替代行情时间 |

新鲜度计算只使用当前身份的快照：

1. 活跃市场传输预算固定为 `max(15,000 ms, 3 × GeneralSettings.refresh_interval_ms)`。Crypto 始终按活跃市场计算；股票在 `session_state.phase=open` 时按活跃市场计算。
2. `now - received_at_utc_ms` 必须大于等于零并且不超过传输预算；负数映射为 `unavailable / clock_invalid`。`now - quote_ts_utc_ms` 位于 `[-5,000 ms, 0)` 时只视为允许的源端时钟偏差，计算新鲜度时取零；小于 `-5,000 ms` 映射为 `unavailable / clock_invalid`。实时行情还要求 `expected_delay_ms=0`，且修正后的行情年龄不超过同一预算；延迟行情要求 `expected_delay_ms` 已由行情源明确声明，且修正后的行情年龄不超过 `expected_delay_ms + 传输预算`。合法模式下超过预算映射为 `stale / age_exceeded`。
3. 股票处于午休或闭市时，若快照属于最近一个真实交易会话，则为 `session_paused`，原因分别为 `session_break` 或 `session_closed`；界面显示最后行情时间，不显示成正在更新。
4. 日历读取失败只让市场时钟显示未知。此时行情仍按活跃市场预算独立判断，完整且新鲜的已收盘 K 线仍可用于分析。
5. `quote_mode=delayed` 缺少 `expected_delay_ms`、`quote_mode=real_time` 却不是零延迟，或 `quote_mode=unknown` 时，一律映射为 `unavailable / incomplete`。合法延迟行情满足时间预算时可判为 `fresh`，但界面必须显示“延迟行情”。
6. K 线新鲜度与报价新鲜度分开判定。开始分析仍以身份一致、完整且新鲜的已收盘 `KlineFrame` 为硬门，不用报价替代 K 线。

失败语义：

| 失败 | 保留内容 | 页面结果 | 分析主动作 |
| --- | --- | --- | --- |
| 首次读取失败或字段不完整 | 不保留数值 | `unavailable / incomplete` | 禁用 |
| 认证失效 | 立即清空报价数值，不沿用旧快照 | `unavailable / auth_failed` | 禁用 |
| 标的、市场、来源、generation 或刷新请求序号不一致 | 丢弃迟到结果，不更新任何可见状态 | 保持当前 generation 的既有状态 | 不变 |
| 同一身份的临时网络失败 | 保留最后权威快照及原时间 | `stale / transport_failed` | 禁用 |
| 当前交易时段内超过新鲜度预算 | 保留最后权威快照及原时间 | `stale / age_exceeded` | 禁用 |
| 日历失败 | 行情按自身时间判断，市场时钟清空 | 行情状态不被伪造，时钟显示未知 | K 线新鲜时可用 |
| 本机或来源时间异常 | 不接受新快照 | `unavailable / clock_invalid` | 禁用 |

任何失败都不得静默切换 TradingView、MT5、AkShare 或其他来源。

#### 按市场设置精确合同

后续生产实现只扩展现有 `GeneralSettings` 和 `config/settings.json`，继续复用当前跨进程锁、`revision` 冲突检查与临时文件原子替换；不得新增第二份设置文件。

| 字段 | 类型 | 默认值 | 约束 |
| --- | --- | --- | --- |
| `market_workspace_schema_version` | `Literal[1]` | `1` | 本合同版本 |
| `last_market` | `US / HK / CN / Crypto / null` | 按当前有效数据源和标的迁移；无唯一证据时为 `null` | 只表示上次页面市场；为 `null` 时等待用户选择，不猜市场 |
| `last_symbols_by_market` | 四个固定键到 `str` | US=`AAPL.US`、HK=`700.HK`、CN=`600519.SH`、Crypto=`XAU-USDT-SWAP` | 每个值必须通过对应市场的规范化与后缀校验 |
| `local_watchlists_by_market` | 四个固定键到 `list[str]` | 四个空列表 | 每个市场最多 100 个；规范化后去重并保持用户顺序 |

设置不保存名称、报价、涨跌、市场时钟、认证状态或分析结果。自选只保存规范化代码；名称与行情每次从只读行情合同重新获取。

旧设置迁移必须是纯函数、幂等且不联网：

1. 先读取 `last_symbols_by_source`。其中 `longbridge` 的合法值只迁入它唯一对应的 US、HK 或 CN，不复制到另外两个市场；`okx` 的合法值只迁入 Crypto。
2. 只有对应来源没有可迁移值时，才检查 `last_symbol`，并且必须能同时由 `last_data_source` 和标的格式唯一确定市场。
3. 不能唯一归类、后缀不合法或来源冲突时不猜测、不删除旧字段、不写部分迁移；本次迁移标记失败，页面显示“旧设置未迁移”，等待用户选择合法标的后再保存。
4. 新结构完整校验通过后，才在同一 `save_settings()` 原子写入中保存四市场结构并递增 `revision`。旧字段在 schema v1 继续保留为兼容镜像，但新页面只读取新结构。
5. 后续每次成功提交市场或标的时，先更新新结构，再派生兼容镜像。当前市场为 US/HK/CN 时，`last_data_source=longbridge`、`last_symbol` 和 `last_symbols_by_source.longbridge` 都写当前市场标的；当前市场为 Crypto 时，`last_data_source=okx`、`last_symbol` 和 `last_symbols_by_source.okx` 写 Crypto 标的，同时保留最后一次合法的 `last_symbols_by_source.longbridge`；`last_market=null` 时不改三个 legacy 当前选择字段。旧字段不得反向覆盖新结构。
6. 本地自选迁移没有旧数据来源，默认保持空列表；不得把预设标的冒充用户收藏。

保存失败语义：

1. 市场、标的或自选已经在当前会话真实生效后，设置保存失败不得回滚已验证的行情连接；页面保留会话状态并明确显示“未保存”。
2. 磁盘文件、磁盘 `revision` 和最后成功保存快照必须保持不变；不得先显示保存成功再回滚。
3. `SettingsConflictError` 不自动覆盖其他窗口。页面保留本次会话草稿和冲突发生前读取的 market-workspace 基线，显示“设置已被其他窗口修改”。
4. “重新载入”明确放弃本次未保存草稿，读取磁盘最新完整设置，并按新的 generation 重新验证市场和标的后提交页面。
5. “再次保存”必须在同一文件锁内读取磁盘最新 revision：只有磁盘中的 market-workspace 字段仍与冲突前基线逐字段相等时，才把本次四市场完整快照合并到磁盘最新的其他设置并原子保存；这些字段已被另一窗口修改时继续报冲突，只允许重新载入，不提供静默覆盖。
6. 设置写入按 generation 串行。只有保存确认的 generation 等于当前已提交 generation 时，才清除“未保存”；旧 generation 的迟到成功不得把新选择标成已保存。
7. 若旧 generation 已先写盘而更新的 generation 尚未保存，页面继续保持“未保存”，并以最新完整设置快照排队保存；禁止只写一个字段造成市场、标的和自选互相矛盾。

### 2.5 状态合同

| 状态 | 页面行为 | 主动作 |
| --- | --- | --- |
| 初次加载 | 固定布局，字段显示等待读取 | 禁用 |
| 市场切换中 | 旧市场保持可辨认，新市场不提前显示成功 | 禁用 |
| 可用且新鲜 | 显示行情、市场时钟和已收盘 K 线证据 | 可用 |
| 午休 | 保留最后可信行情并标出更新时间 | 可用，分析只读已收盘数据 |
| 闭市 | 显示下一开市时间 | 可用，分析只读已收盘数据 |
| 半日市 | 明确显示半日市和提前收盘时间 | 按数据新鲜度决定 |
| 加密连续交易 | 显示连续交易和 UTC 时间 | 按数据新鲜度决定 |
| 行情已过期 | 仅在标的和来源身份仍一致时保留最后一次已确认值，同时显示已过期和采集时间 | 禁用 |
| 日历失败 | 市场阶段显示未知 | 行情新鲜时仍可分析，不把日历当交易闸门 |
| 认证失效 | 清空行情值，保留市场与标的选择 | 禁用 |
| 标的不支持 | 不自动猜市场，不自动换源 | 禁用 |
| 分析中 | 锁定本轮市场、标的和周期 | 只允许取消分析 |
| 分析失败 | 保留本轮输入证据和错误原因 | 允许重新开始 |

行情从未成功确认、认证失效，或行情的标的、市场、来源与当前选择不一致时，必须清空数值，不能沿用旧值。K 线新鲜度按“该市场最近一个应当完成的交易槽 + 当前周期 + 明确宽限”判断；闭市后的墙钟时间增长本身不能把最后一根合法收盘 K 线误判为过期。

#### 界面文案清单

本节只列未来界面允许出现的固定文案；本文其他说明属于设计文档，不是界面副标题或辅助小字。

| 用途 | 允许文案 |
| --- | --- |
| 页面标题 | 多市场看盘 |
| 市场 | 美股、港股、A股、加密 |
| 字段 | 标的、市场状态、行情状态、数据来源、最新行情、涨跌额、涨跌幅、更新时间、周期、最新收盘、K线根数、分析状态 |
| 主动作 | 开始分析、取消分析 |
| 次动作 | 刷新行情、添加自选、移除自选、重新载入、再次保存 |
| 市场状态 | 开市、午休、闭市、半日市、连续交易、状态未知 |
| 行情状态 | 实时行情、延迟行情、行情已过期、行情不可用、认证失效 |
| 切换状态 | 切换中、切换失败 |
| 保存状态 | 未保存、设置已被其他窗口修改 |
| 分析状态 | 未开始、准备中、分析中、已完成、失败、已取消 |

界面不得增加标题下解释、灰色辅助小字、括号注释、营销口号、重复说明或小号页脚。动态错误只显示完成下一步所必需的业务原因，并使用正文或更高层级字号；内部异常栈、SDK 类型、请求 ID 和原始载荷不进入普通界面。

### 2.6 交互合同

#### 市场切换

| 页面市场 | 数据源 | 合法标的后缀 |
| --- | --- | --- |
| US | Longbridge | `.US` |
| HK | Longbridge | `.HK` |
| CN | Longbridge | `.SH`、`.SZ` |
| Crypto | OKX | OKX 现有标准化合约标识 |

1. 用户选择 US、HK、CN 或 Crypto，页面先进入切换中状态。
2. 先校验目标标的与市场后缀一致；不一致就拒绝，不猜市场。
3. 数据源真的变化时，复用既有 `_switch_data_source(kind)` 完成跨数据源事务。
4. US、HK、CN 之间切换时不重复切换 Longbridge；使用待新增的 Longbridge 内市场事务，同时更新目标标的、按市场最近标的和页面状态。
5. 连接、验证、订阅或页面提交失败时，恢复旧市场的完整可用状态并显示真实错误。
6. 新数据源、市场、标的和状态全部确认后，再一次性替换页面。
7. 页面已经成功切换后，若本地设置保存失败，保留本次会话中已生效的选择，明确显示“未保存”；不能谎称已完整回滚。
8. 不允许失败后静默切到 TradingView、MT5、AkShare 或其他来源。

##### generation 与并发规则

1. 页面维护一个只增不减的 `selection_generation`。用户每次提交市场、标的或周期的新组合时先加一，并把该 generation 下各请求族的最新刷新序号重置为零；同一选择的刷新不增加 generation，但每次发起报价、K 线或静态信息刷新时，都必须把对应请求族的 `request_sequence` 加一。
2. 所有连接、静态信息、报价、K 线、订阅、设置保存和分析回调都必须携带发起时的 generation，以及完整 `market + source + symbol + timeframe`。报价、K 线和静态信息刷新回调还必须携带各自发起时的 `request_sequence`。
3. 页面同时只有一个“已提交选择”和一个“切换中选择”。切换期间旧选择继续显示并标明切换中，新选择不得提前覆盖标题、行情、K 线或详情。
4. 用户在切换完成前再次选择时，新请求获得更大 generation。可取消的旧请求立即取消；不可取消的 SDK 调用允许返回，但结果只做资源释放。
5. 任何回调在写入页面、缓存、设置或分析记录前，都必须比较 generation 和完整身份。报价、K 线和静态信息刷新回调还必须比较本请求族的 `request_sequence`；只有序号等于该 generation 下最新已发出序号时才可写入。较小 generation、旧刷新序号或身份不一致的成功与失败结果都直接丢弃，禁止显示错误、清除较新状态、恢复旧值、写设置或触发分析。
6. 设置保存使用单队列串行。只有最新已提交 generation 的完整设置快照可以成为“已保存”状态；旧保存完成后若已有更新选择，页面仍显示未保存并排队最新快照。
7. 分析提交时冻结 generation 和完整身份。分析完成后仍归属原市场与原标的；用户已切换时，不得把旧结果渲染成当前标的结果。

##### Longbridge 内 US、HK、CN 切换

1. 复用同一个已认证 Longbridge 只读上下文，不断开重连，也不创建第二个行情真值。
2. 先在内存中规范化并验证市场后缀，再用目标 generation 请求静态信息、订阅、报价和已收盘 K 线；旧订阅与旧页面在提交点前保持可用。
3. 只有以下条件同时成立才提交：目标标的存在；市场、来源和标的一致；目标周期受支持；首份报价身份一致；首份已收盘 K 线身份一致且满足完整性门禁。
4. 提交时一次性替换市场、标的、周期、报价、K 线、市场时钟和详情读模型，然后停止旧订阅；不得逐块更新造成混合市场。
5. 提交前任何一步失败，继续使用旧提交状态并显示目标请求的真实错误。若 SDK 已部分改变订阅，必须重新订阅并核验旧身份后才能声称回滚成功。
6. 旧身份恢复也失败时，不得显示旧页面仍可用；清空报价与 K 线，进入“切换失败”，禁用分析，等待用户重试。
7. Longbridge 认证失效会让 US、HK、CN 三个市场共同不可用，但不得影响已经独立验证的 OKX Crypto 状态。

##### Longbridge 与 OKX 跨数据源切换

1. 复用现有 `_switch_data_source(kind)` 的“先建立新源、后提交、最后释放旧源”事务边界，并把 generation 检查扩展到所有异步回调。
2. 切到 Crypto 时，目标来源只能是 OKX；切回 US、HK 或 CN 时，目标来源只能是 Longbridge。不得只换页面市场而保留错误数据源。
3. 新数据源在独立暂存状态完成连接、标的验证、订阅、报价与 K 线首读前，旧数据源保持运行。
4. 新 generation 取代旧请求时，必须关闭旧请求创建但尚未提交的数据源；不得断开当前已提交数据源。
5. 提交成功后再释放旧数据源。释放失败只记录为资源错误，不回滚已经验证的新状态；但不得留下仍向页面发回调的旧刷新线程。
6. 跨源失败回滚、迟到结果和设置保存继续使用上述统一 generation 规则，不为 OKX 或 Longbridge增加例外。

#### 标的与自选

1. `_symbol_combo` 继续作为当前标的唯一选择入口。
2. `last_symbols_by_source` 继续服务已有数据源记忆；本页另增按 US、HK、CN、Crypto 保存的最近标的，不能把三个 Longbridge 市场挤进同一槽位。
3. 添加、删除和排序只写待新增的本地 `GeneralSettings` 按市场自选结构。
4. 不调用长桥云端 watchlist 写接口。
5. 删除本地自选不影响历史分析记录。

#### 市场时钟

1. 股票市场使用 `session_state` 的 phase、is_half_day 和 next_change_utc_ms。
2. phase 映射为开市、午休、闭市。
3. 半日市作为独立状态显示。
4. 下一变化时间按交易所当地时区显示，并明确时区名称。
5. 日历读取失败时显示状态未知，不用本机时间猜测；它只关闭市场时钟事实，不阻断对完整且新鲜的已收盘 K 线做只读分析。

#### 分析

1. 开始分析时冻结市场、标的、周期、数据源和最新已收盘 K 线。
2. 分析过程中切换市场必须先取消当前分析或等待完成。
3. 完成后结果仍绑定原市场与原标的，不能被新选择覆盖。
4. 交易时段和高周期背景只解释环境，不改变主周期硬结论。

### 2.7 角色合同

| 角色 | 可见与可操作 | 禁止请求 |
| --- | --- | --- |
| Owner | 四市场、全部本地自选、行情证据、两阶段分析、连接诊断详情 | 本页不请求下单、撤单、仓位、保护单或风险控制写接口 |
| 普通付费用户 | 扩展自选、行情证据、分析摘要、提醒和导出 | 不请求执行、券商、调度器、实例、风险开关或原始提示词 |
| 普通免费用户 | 有限标的、市场状态、基础行情、有限分析摘要 | 与付费用户相同，并且不预取锁定功能的数据 |
| 未知角色 | 只读基础市场状态 | 所有写请求和受限数据请求 |

当前 PyQt6 桌面产品以 Owner 使用为主。普通角色是后续产品边界，本轮不实现权限系统。

## 5. 三个视觉方向

本节冻结三套候选稿的业务与布局意图，不把文字说明冒充视觉稿。Product Design 的实际提示词、脱敏附件、产物标识、文件和人工复核记录统一登记在 `docs/prd/06_WO-E_Product_Design_三方向证据.md`。

### 方向 A：专业工作站

适合频繁切换标的、同时观察多个状态的 Owner。

布局：

- 顶部 44px 市场标签与全局数据状态。
- 左侧 240px 本地自选，按市场分组。
- 中央为 K 线、周期切换和分析结果。
- 右侧 340px 固定详情栏，显示报价、市场时钟和数据证据。
- 底部只放分析历史，可折叠。

特点：

- 信息密度最高。
- 市场切换和自选扫描最快。
- 最接近长桥工作站节奏。

风险：

- 1440×900 下需要严格控制列宽。
- 不适合作为未来普通用户默认页。

### 方向 B：证据优先

适合先判断数据是否可靠，再开始分析。推荐作为下一阶段首选。

布局：

- 顶部用一行完成市场、标的、市场时钟和新鲜度判断。
- 左侧 220px 只放当前市场自选。
- 中央上方为 K 线，下方为最近两阶段分析。
- 右侧 360px 按市场状态、行情来源、已收盘 K 线和分析输入分组。
- 详细诊断进入抽屉。

特点：

- 主问题最清楚。
- 认证失败、陈旧数据和日历未知不容易混淆。
- 与现有 PA_Agent 的证据分层方向一致。

风险：

- 同屏可见的自选数量少于方向 A。
- 高频扫描需要更多滚动。

### 方向 C：市场切换优先

适合跨美股、港股、A股和加密快速巡视。

布局：

- 顶部第一行是四市场切换和市场时钟。
- 第二行是横向自选带与搜索。
- 中央使用更宽的 K 线和行情摘要。
- 右侧详情默认收起，选中证据或分析结果时展开。
- 分析历史放在中央下方。

特点：

- 四市场边界最明显。
- 中央图表空间最大。
- 学习成本最低。

风险：

- 横向自选在 1440px 下必须限制可见数量。
- 右侧详情展开时中央宽度变化，需要稳定动画和焦点管理。

## 6. 方向选择门

用户确认方向前必须先完成三套可见的 Product Design 高保真候选稿，但不进入方向绑定设计和生产代码。

允许继续：

1. 核对现有代码、数据模型、持久化和错误语义，并修正文档中的事实差异。
2. 补齐 `QuoteSnapshot`、页面读模型、按市场设置、generation、回滚和迟到结果合同。
3. 补齐正常、空数据、认证失败、陈旧、日历未知、保存失败和并发竞态验收矩阵。
4. 整理脱敏素材清单、附件清单和外部工具输入门禁。
5. 调用 Product Design `ideate` 独立生成三套以 1440×900 为目标比例和密度的高保真方向候选稿；ImageGen 原生画布可以是近似同比例尺寸，但选择前只比较信息层级与视觉方向，不冒充精确尺寸验收。每套同时呈现可信正常数据和至少一个真实风险或错误状态。
6. 记录提示词、产物标识、文件、SHA-256，并完成候选稿级 Product Design 视觉复核；该复核只判断是否足以让用户选方向，不是方向绑定的精修或生产视觉验收，也不替用户填写选择结果。

禁止继续：

1. 不代选 A、B 或 C；“推荐 B”不是用户确认。
2. 不生成方向绑定的 ChatGPT Web PRD，不调用 Stitch、候选稿之外的图像精修或项目级 `$design-taste-frontend` 生产视觉审计；候选稿级 Product Design 视觉复核不在此禁令内。
3. 不修改 PyQt6、QSS、设置模型、数据源、读模型或测试代码。
4. 不运行真实 Longbridge 三标的验收，不把阶段 0/1 文档完成写成 WO-E 完成。

选择时只比较四件事：

1. 目标比例下的信息层级与预计可读性；精确 1440×900 的字号和可读性只在用户选定方向后的第一轮精修验收。
2. 切换市场和标的的速度。
3. 数据异常是否一眼可辨。
4. Owner 密度与未来普通角色简化的兼容性。

文字合同倾向方向 B，但这不是用户选择，也不能覆盖三套实际候选稿的显示顺序。

本节约束候选稿与后续外部设计阶段的全部输入。实际附加给图像生成工具的文件必须先进入逐文件清单；未列入清单的本地参考不得上传。

| 输入 | 允许保留 | 必须替换或删除 |
| --- | --- | --- |

| 错误状态 | 认证失效、网络失败、行情已过期、日历未知、保存失败等稳定业务类别 | 原始 SDK 异常、堆栈、请求 ID、Cookie、响应载荷和日志行 |
| 代码结构 | 相对模块名、公开类名、只含签名的脱敏接口摘要 | API Key、Secret、Token、Passphrase、环境文件、数据库和生产配置 |
| 长桥结构参考 | 公开可访问页面的分区、密度、表格和详情栏规律 | 品牌标识、原文、图标、精确坐标、订单面板和受版权保护的完整页面 |
| OKX 与 PA_Agent | `OKX Demo`、`Longbridge`、`PyQt6` 等公共产品或技术名称 | 账户 ID、账户身份摘要、真实仓单、风险高水位和券商日志 |

每次提交前必须生成附件清单，每项记录：文件名、用途、来源、是否合成、删除或替换内容、敏感信息扫描结果和文件 SHA-256。以下内容一律不得进入 ChatGPT Web、Stitch 或图像生成输入：

1. API Key、Secret、Token、Passphrase、Cookie、证书和环境文件。
2. 账户 ID、姓名、邮件、交易密码和账户身份摘要。
3. 数据库、日志、原始 prompt、完整模型回复和生产配置。
4. 真实订单、成交、持仓、资金、盈亏、资金流水和可还原交易行为的时间序列。
5. 本机用户名、绝对私有路径、内部 URL、进程信息和未公开仓库内容。

脱敏后仍无法确认安全的材料不提交。原型可使用明确标注的合成值，正式实现不得把合成值带入生产路径。

## 9. 二元验收

### 9.1 场景矩阵

所有场景同时要求：

1. 状态使用文字和图标，不只靠颜色。
2. 页面只使用第 2.5 节界面文案清单，不出现副标题、说明性小字、括号注释或小号页脚。
3. 全程只读行情与两阶段分析，不请求下单、撤单、仓位、保护单或风险控制写接口。
4. 离屏验收覆盖 1440×900 和 1920×1080；最终桌面验收由用户从正式快捷方式启动。

### 9.2 本阶段文档验收

1. 文档包含主问题、主对象、主动作、字段、状态、交互、角色和允许的数据请求。
2. 三个方向在布局、密度和主路径上有实质差异。
3. `QuoteSnapshot` 字段、数值不变量、新鲜度、延迟和失败语义均为二元可测。
4. 四市场最近标的与本地自选 schema、旧设置迁移和保存失败语义完整。
5. Longbridge 内市场切换与 Longbridge↔OKX 跨源切换均有 generation、提交、回滚和迟到结果规则。
6. 连接、验证、订阅和页面提交失败会回滚；设置持久化失败保留本次会话状态并明确显示未保存；任何失败都不静默换源。
7. 自选只写本地设置，不保存报价或名称。
8. 市场时钟来自真实日历合同。
9. 加密不使用股票会话语义。
10. 认证失败、身份不一致、陈旧数据和标的不支持不会显示成可用；日历未知显示未知，但不伪装成分析硬闸。
11. 验收矩阵覆盖 US、HK、CN、Crypto、跨源切换、保存失败和 generation 竞态。
12. 脱敏输入清单明确禁止凭据、账户、日志、数据库和真实交易数据。
13. 界面文案清单中副标题、eyebrow、tagline、标题下解释、灰色辅助小字、括号注释、营销口号、重复说明和小号页脚均为 0。
14. 本页没有交易写操作。
15. 页面字号不低于 14px，状态不只靠颜色。
16. 本轮只调用 Product Design `ideate` 生成三套候选稿；没有代选 A/B/C，没有调用 Stitch、方向绑定 PRD、图像精修或生产实现，没有修改 PyQt6 生产代码，也不宣称完成 WO-E。

### 9.3 Product Design 候选稿验收

1. 三张图由三个独立 ImageGen 调用生成，每次一张，并按本次对话中的实际显示顺序登记为 1、2、3。
2. 三张图均为单一桌面主屏，布局主轴分别为左侧高密扫描、顶部证据门和四市场罗盘，存在实质差异。
3. 三张图均同时显示可信正常数据和至少一个风险或错误状态。
4. 三张图均未显示买入、卖出、订单、撤单、账户、资产、持仓、杠杆或自动交易控件。
5. ImageGen 原生产物为 1586×992，宽高比与 1440×900 目标相差小于 0.1%，但不是精确验收尺寸；用户选定方向后的第一轮精修必须输出精确目标画布。
6. 候选稿只用于审美与信息层级选择。图中任何未进入第 2.5 节文案清单的辅助文字、括号注释、技术指标或尺寸偏差都不是生产合同，必须在方向确认后的精修中清除。
