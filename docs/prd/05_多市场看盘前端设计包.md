# 多市场看盘前端设计包

## 1. 本轮范围

本文件冻结多市场看盘页的页面合同，并提供三个可供用户选择的视觉方向。

本轮只交设计，不修改 PyQt6 代码。用户选择方向后，才进入网页版 ChatGPT PRD、Stitch、三轮图像精修、视觉审计和生产实现。

设计真值按以下顺序使用：

1. `D:\Desktop\Quant\前端设计\DESIGN.md`
2. 当前 PA_Agent 数据合同与状态语义
3. `CONTEXT.md`、`lessons.md`、`docs/WORKORDER_MASTER_20260727.md`
4. 长桥参考素材中的工作站结构、密度、切换节奏和右侧详情栏

只吸收公开可辨认的结构规律，不复制品牌、原文、图标、精确坐标、订单面板或交易外观。

## 2. 页面合同

### 2.1 主问题

用户必须在五秒内看清：

1. 当前市场和标的是什么。
2. 市场现在处于什么阶段。
3. 行情和已收盘 K 线是否新鲜。
4. 当前可以查看、切换或开始哪项分析。

### 2.2 主对象与主动作

- 主对象：当前市场下的当前标的。
- 主动作：开始两阶段价格行为分析。
- 次动作：切换市场、切换标的、管理本地自选、刷新行情。
- 明确排除：买入、卖出、加仓、撤单、离场、券商路由、自动交易开关。

### 2.3 首屏对象预算

首屏只保留六个顶层对象：

1. 市场切换。
2. 当前标的与本地自选。
3. 市场时钟。
4. 行情新鲜度。
5. K 线与分析主区。
6. 右侧证据详情。

原始数据、连接诊断、完整日历信息和历史分析下沉到抽屉或详情页。

### 2.4 字段合同

| 区域 | 必须显示 | 数据来源 | 不可信时 |
| --- | --- | --- | --- |
| 市场切换 | 美股、港股、A股、加密 | 待新增的页面市场状态与市场路由表 | 保留原选择并显示无法切换 |
| 标的选择 | 代码、名称、所属市场 | 当前数据源符号列表；名称依赖待新增行情合同 | 不显示旧名称冒充新标的 |
| 本地自选 | 代码、名称、最新价、涨跌、更新时间 | 待新增的按市场本地自选结构与只读行情合同 | 单行显示已过期或读取失败 |
| 市场时钟 | 开市、午休、闭市、半日市、下一变化时间 | `market_calendar.session_state` | 显示状态未知，不猜下一时刻 |
| 加密时钟 | 连续交易、当前 UTC 时间 | 连续市场规则 | 不套用股票开盘和尾盘 |
| 行情摘要 | 最新价、涨跌额、涨跌幅、最新行情时间 | 待新增的只读 `QuoteSnapshot` 合同 | 按下文的可信度规则保留或清空 |
| K 线证据 | 周期、最新已收盘 K 线时间、根数、数据源 | `KlineFrame` | 阻止开始新分析并显示原因 |
| 分析状态 | 未开始、准备中、分析中、已完成、失败、已取消 | 现有两阶段分析状态 | 不把失败显示成等待 |
| 右侧详情 | 当前标的证据、市场状态、数据来源、最近分析摘要 | 只读模型与分析记录 | 逐项标记未知 |

涨跌默认采用红涨绿跌。涨跌值必须同时带正负号，不能只靠颜色。系统健康、警告和阻断使用独立颜色语义。

#### 现有读取路径与生产缺口

| 能力 | 当前真实状态 | 生产实现前的动作 |
| --- | --- | --- |
| 已收盘 K 线 | `KlineFrame` 已有标的、周期、OHLCV、开盘时间和收盘标记 | 可直接显示最新已收盘 K 线的收盘价、时间和根数 |
| 市场日历 | `market_calendar.session_state` 已有阶段、半日市和下一变化时间 | 只把它用于市场时钟和解释性标签 |
| 跨数据源切换 | `_switch_data_source(kind)` 已按数据源执行连接、验证与订阅事务 | 只用于数据源真的变化时，不冒充同一 Longbridge 内的市场切换 |
| 最近标的 | `last_symbols_by_source` 目前只按数据源保存 | 新增按 US、HK、CN、Crypto 分开的最近标的状态 |
| 本地自选 | 目前没有本页所需的按市场自选结构 | 在 `GeneralSettings` 新增按市场保存的自选结构后才能接线 |
| 实时行情摘要 | 通用 `DataSource` 不保证名称、最新价、涨跌和行情时间；Longbridge 的静态信息没有保留成页面读模型 | 先新增纯只读 `QuoteSnapshot`，至少含 symbol、market、name、last、change、change_pct、quote_ts、source 和 freshness |

`QuoteSnapshot` 和按市场设置结构完成前，页面只能把最新已收盘 K 线的收盘价与时间明确标成“K 线收盘”，不能冒充实时行情。

### 2.5 状态合同

| 状态 | 页面行为 | 主动作 |
| --- | --- | --- |
| 初次加载 | 固定布局，字段显示等待读取 | 禁用 |
| 市场切换中 | 旧市场保持可辨认，新市场不提前显示成功 | 禁用 |
| 可用且新鲜 | 显示行情、市场时钟和已收盘 K 线证据 | 可用 |
| 午休 | 保留最后可信行情并标出更新时间 | 可用，分析只读已收盘数据 |
| 闭市 | 显示下一开市时间 | 可用，分析只读已收盘数据 |
| 半日市 | 明确显示半日市和提前收盘时间 | 按数据新鲜度决定 |
| 加密连续交易 | 显示连续交易和 UTC 时间 | 按数据新鲜度决定 |
| 行情已过期 | 仅在标的和来源身份仍一致时保留最后一次已确认值，同时显示已过期和采集时间 | 禁用 |
| 日历失败 | 市场阶段显示未知 | 行情新鲜时仍可分析，不把日历当交易闸门 |
| 认证失效 | 清空行情值，保留市场与标的选择 | 禁用 |
| 标的不支持 | 不自动猜市场，不自动换源 | 禁用 |
| 分析中 | 锁定本轮市场、标的和周期 | 只允许取消分析 |
| 分析失败 | 保留本轮输入证据和错误原因 | 允许重新开始 |

行情从未成功确认、认证失效，或行情的标的、市场、来源与当前选择不一致时，必须清空数值，不能沿用旧值。K 线新鲜度按“该市场最近一个应当完成的交易槽 + 当前周期 + 明确宽限”判断；闭市后的墙钟时间增长本身不能把最后一根合法收盘 K 线误判为过期。

### 2.6 交互合同

#### 市场切换

| 页面市场 | 数据源 | 合法标的后缀 |
| --- | --- | --- |
| US | Longbridge | `.US` |
| HK | Longbridge | `.HK` |
| CN | Longbridge | `.SH`、`.SZ` |
| Crypto | OKX | OKX 现有标准化合约标识 |

1. 用户选择 US、HK、CN 或 Crypto，页面先进入切换中状态。
2. 先校验目标标的与市场后缀一致；不一致就拒绝，不猜市场。
3. 数据源真的变化时，复用既有 `_switch_data_source(kind)` 完成跨数据源事务。
4. US、HK、CN 之间切换时不重复切换 Longbridge；使用待新增的 Longbridge 内市场事务，同时更新目标标的、按市场最近标的和页面状态。
5. 连接、验证、订阅或页面提交失败时，恢复旧市场的完整可用状态并显示真实错误。
6. 新数据源、市场、标的和状态全部确认后，再一次性替换页面。
7. 页面已经成功切换后，若本地设置保存失败，保留本次会话中已生效的选择，明确显示“未保存”；不能谎称已完整回滚。
8. 不允许失败后静默切到 TradingView、MT5、AkShare 或其他来源。

#### 标的与自选

1. `_symbol_combo` 继续作为当前标的唯一选择入口。
2. `last_symbols_by_source` 继续服务已有数据源记忆；本页另增按 US、HK、CN、Crypto 保存的最近标的，不能把三个 Longbridge 市场挤进同一槽位。
3. 添加、删除和排序只写待新增的本地 `GeneralSettings` 按市场自选结构。
4. 不调用长桥云端 watchlist 写接口。
5. 删除本地自选不影响历史分析记录。

#### 市场时钟

1. 股票市场使用 `session_state` 的 phase、is_half_day 和 next_change_utc_ms。
2. phase 映射为开市、午休、闭市。
3. 半日市作为独立状态显示。
4. 下一变化时间按交易所当地时区显示，并明确时区名称。
5. 日历读取失败时显示状态未知，不用本机时间猜测；它只关闭市场时钟事实，不阻断对完整且新鲜的已收盘 K 线做只读分析。

#### 分析

1. 开始分析时冻结市场、标的、周期、数据源和最新已收盘 K 线。
2. 分析过程中切换市场必须先取消当前分析或等待完成。
3. 完成后结果仍绑定原市场与原标的，不能被新选择覆盖。
4. 交易时段和高周期背景只解释环境，不改变主周期硬结论。

### 2.7 角色合同

| 角色 | 可见与可操作 | 禁止请求 |
| --- | --- | --- |
| Owner | 四市场、全部本地自选、行情证据、两阶段分析、连接诊断详情 | 本页不请求下单、撤单、仓位、保护单或风险控制写接口 |
| 普通付费用户 | 扩展自选、行情证据、分析摘要、提醒和导出 | 不请求执行、券商、调度器、实例、风险开关或原始提示词 |
| 普通免费用户 | 有限标的、市场状态、基础行情、有限分析摘要 | 与付费用户相同，并且不预取锁定功能的数据 |
| 未知角色 | 只读基础市场状态 | 所有写请求和受限数据请求 |

当前 PyQt6 桌面产品以 Owner 使用为主。普通角色是后续产品边界，本轮不实现权限系统。

## 4. 长桥结构吸收

### 采用

- 稳定的市场与标的切换。
- 左侧自选、中央工作区、右侧详情栏。
- 紧凑标签、低对比边界、等宽数字和固定表头。
- 中央对象切换时右侧证据同步更新。
- Owner 桌面可使用较高信息密度。

### 调整

- 不复制订单面板和券商账户详情。
- 不复制品牌、图标、文字、精确坐标和布局比例。
- 普通角色降低密度，并完全移除执行机制。
- PA_Agent 保留原生 PyQt6，不引入 WebView 或第二套前端。

## 5. 三个视觉方向

### 方向 A：专业工作站

适合频繁切换标的、同时观察多个状态的 Owner。

布局：

- 顶部 44px 市场标签与全局数据状态。
- 左侧 240px 本地自选，按市场分组。
- 中央为 K 线、周期切换和分析结果。
- 右侧 340px 固定详情栏，显示报价、市场时钟和数据证据。
- 底部只放分析历史，可折叠。

特点：

- 信息密度最高。
- 市场切换和自选扫描最快。
- 最接近长桥工作站节奏。

风险：

- 1440×900 下需要严格控制列宽。
- 不适合作为未来普通用户默认页。

### 方向 B：证据优先

适合先判断数据是否可靠，再开始分析。推荐作为下一阶段首选。

布局：

- 顶部用一行完成市场、标的、市场时钟和新鲜度判断。
- 左侧 220px 只放当前市场自选。
- 中央上方为 K 线，下方为最近两阶段分析。
- 右侧 360px 按市场状态、行情来源、已收盘 K 线和分析输入分组。
- 详细诊断进入抽屉。

特点：

- 主问题最清楚。
- 认证失败、陈旧数据和日历未知不容易混淆。
- 与现有 PA_Agent 的证据分层方向一致。

风险：

- 同屏可见的自选数量少于方向 A。
- 高频扫描需要更多滚动。

### 方向 C：市场切换优先

适合跨美股、港股、A股和加密快速巡视。

布局：

- 顶部第一行是四市场切换和市场时钟。
- 第二行是横向自选带与搜索。
- 中央使用更宽的 K 线和行情摘要。
- 右侧详情默认收起，选中证据或分析结果时展开。
- 分析历史放在中央下方。

特点：

- 四市场边界最明显。
- 中央图表空间最大。
- 学习成本最低。

风险：

- 横向自选在 1440px 下必须限制可见数量。
- 右侧详情展开时中央宽度变化，需要稳定动画和焦点管理。

## 6. 方向选择门

用户确认方向前只允许继续补充合同和状态，不进入生产代码。

选择时只比较四件事：

1. 1440×900 下的可读性。
2. 切换市场和标的的速度。
3. 数据异常是否一眼可辨。
4. Owner 密度与未来普通角色简化的兼容性。

推荐方向 B。它最符合当前系统的失败关闭原则，也最容易把行情、日历和分析输入的证据分开。

## 7. 后续设计流程

方向确认后按顺序执行：

1. 用本合同生成完整 PRD。
2. 把脱敏现状材料、长桥结构参考和 PRD 提交到登记的 Stitch 项目。
3. 至少完成三轮图像精修，每轮都检查状态、密度、文字和布局。
4. 完成视觉审计并记录采用、调整和拒绝的参考。
5. 再转换为 PyQt6、QWidget、QSS 和 pyqtgraph。
6. 接入真实读模型、设置持久化和状态响应。
7. 用离屏夹具验证 1440×900 与 1920×1080。
8. 最终桌面验收由用户从 `D:\Desktop\PA_Agent.lnk` 启动。

## 8. 二元验收

1. 文档包含主问题、主对象、主动作、字段、状态、交互、角色和允许的数据请求。
2. 三个方向在布局、密度和主路径上有实质差异。
3. 连接、验证、订阅和页面提交失败会回滚；设置持久化失败保留本次会话状态并明确显示未保存；任何失败都不静默换源。
4. 自选只写本地设置。
5. 市场时钟来自真实日历合同。
6. 加密不使用股票会话语义。
7. 认证失败、身份不一致、陈旧数据和标的不支持不会显示成可用；日历未知显示未知，但不伪装成分析硬闸。
8. 本页没有交易写操作。
9. 页面字号不低于 14px，状态不只靠颜色。
10. 本轮没有修改 PyQt6 生产代码，也不宣称完成 WO-E。
