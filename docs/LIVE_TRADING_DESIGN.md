# PA_Agent 实盘交易闭环设计

## 目标

把已经持久化并通过程序校验的 PA 阶段二结果接入一个可恢复的交易生命周期：

1. 读取方向、入场方式、入场价、两档止盈和止损。
2. 使用用户明确配置的券商、账户、产品、品种和数量生成执行计划。
3. 完成预检、入场提交、成交/部分成交监控、保护单、主动离场。
4. 持续读取订单、持仓、资金、已实现/未实现盈亏并回写 PA。
5. 重启后从本地执行账本恢复，不重复下单。

支持范围：

- Longbridge：模拟、综合或日内融资子账户；日内账户可在安全条件下回退综合账户，模拟账户与实盘完全隔离。
- OKX：现货与永续合约；品种由配置和交易所实时规格决定，不硬编码黄金。

## 非目标

- 不重做 PA 前端视觉。
- 不把 PA 改造成多策略、多用户或跨项目通用交易平台。
- 不让大模型决定券商、账户、品种、数量、杠杆或是否启用实盘。
- 不在开发、自动化测试或只读连通性检查中发送真实订单。

## 可信边界

模型输出只允许提供：

- `order_direction`
- `order_type`
- `entry_price`
- `take_profit_price`
- `take_profit_price_2`
- `stop_loss_price`
- `trade_confidence`

券商、产品、账户、品种、数量、保证金模式和实盘开关只来自本地配置。模型返回的同名扩展字段全部忽略。

执行前必须满足：

- 分析记录已经原子写盘并可重新读取。
- 不是演示回放、历史重放或异常/短路记录。
- `order_type != 不下单`，价格为有限正数，方向和价格顺序一致。
- 交易置信度达到独立的实盘门槛。
- 当前分析品种与配置的来源品种完全相同。
- 券商返回的品种状态、最小数量、步长、价格跳动和可用数量均通过。

## 最小模块

```text
AnalysisRecord
    -> PlanBuilder（只读取白名单字段）
    -> ExecutionStore（SQLite，命令/状态/事件原子持久化）
    -> ExecutionService（会话开关、幂等、轮询、重启对账）
         -> LongbridgeAdapter
         -> OkxAdapter
    -> EventBus
    -> TradingDialog（配置、只读测试、启停、账户/盈亏、撤单/平仓）
```

只允许一个活动执行目标；用户可在 Longbridge 与 OKX 间选择。这样避免同一分析被意外同时发送到两个实盘账户。

## 状态

```text
READY
  -> SUBMITTING
  -> ENTRY_PENDING
  -> PARTIALLY_FILLED（立即撤剩余数量）
  -> OPEN
  -> EXIT_PENDING
  -> CLOSED

需对账/终止：
UNKNOWN（仍会只读对账）、BLOCKED、CANCELED、REJECTED、ERROR
```

`UNKNOWN` 表示请求可能已到达券商但本地无法确认。进入该状态后禁止再次提交，必须先按客户订单号/备注对账。

## 写操作开关

真实订单必须同时满足：

1. 共享环境文件中的 `PA_AGENT_LIVE_TRADING_ENABLED=true`。
2. OKX Live 还要求 `OKX_LIVE_ENABLED=true`；模拟交易不要求。
3. 当前 PA 进程内完成一次会话启用确认，且只对当时选中的券商开放写操作。
4. 目标配置启用并通过只读预检。

Longbridge 模拟账户不使用实盘总开关，改为要求 `PA_AGENT_PAPER_TRADING_ENABLED=true` 和本次进程输入 `启用模拟交易`。模拟计划标记为 `demo`；切换到综合/日内后会话立即停用，必须重新满足实盘开关与确认文字。

会话启用状态不落盘，PA 重启后一定恢复为停用。自动执行只能在本次会话已经启用时生效。

## Longbridge

### 凭据命名

- 模拟账户：`LONGBRIDGE_PAPER_*`
- 综合账户：`LONGBRIDGE_COMPREHENSIVE_*`
- 日内融资账户：`LONGBRIDGE_INTRADAY_*`
- 旧的 `LONGBRIDGE_*` 仅作为综合账户兼容来源。

每个档案还必须配置对应的 `*_ACCOUNT_ID`。创建 SDK 上下文前，凭据加载器会解析 Legacy Token 的签名载荷，核对 `paper` / `live` 类型和绑定账户 ID；Token 无法解析、类型错放或账户 ID 不一致时一律失败，不允许仅凭环境变量名称推断账户。

每个账户建立独立 `TradeContext`、`HttpClient` 和账户状态，不混用 Token。

### 账户选择与回退

1. 对首选账户调用官方最大可交易数量估算。
2. 首选模拟或综合账户时不回退；模拟账户永远不能跨到实盘账户。
3. 首选日内账户且估算数量不足时，若用户开启回退，再预检综合账户。
4. 综合账户足量才选择综合账户。
5. 认证失败、网络失败、超时、限流、提交中或任何未知状态都禁止回退。
6. 一旦调用过提交接口，本次执行永远不能换账户。
7. 模拟账户只允许常规交易时段，不接受盘前/盘后配置。

界面路由字段一旦改变，当前会话立即停用，并在保存前禁用启用、提交、撤单和离场操作。保存后服务从同一份设置快照重新加载路由，用户必须再次输入与目标环境匹配的确认文字。

### 入场与保护

- 限价单：`LO`
- 市价单：`MO`
- 突破单：`MIT`
- 原始 HTTP 提交携带 `client_request_id`；备注携带 PA 执行短 ID，供超时对账。
- 部分成交时立即撤销未成交数量，按实际成交量管理。
- 券商只返回“已成交”但缺少成交数量时，必须从当日/历史成交明细按订单号汇总数量与加权均价；无法确认时进入人工关注并停止写操作，禁止退回计划数量。
- 成交后建立一笔覆盖剩余仓位的券商端 `MIT` 止损。
- Longbridge 不支持附加单/OCO。止盈由 PA 轮询实时价格：
  1. 持久化“准备减仓”；
  2. 撤销并确认旧止损；
  3. 市价减仓；
  4. 按剩余仓位重建止损。
- 重启时若发现持仓存在而止损缺失，先恢复止损，再继续止盈监控。
- 撤销止损一旦已提交或结果未知，后续轮询只查询原止损状态，不重复发送撤单。

### 资金与盈亏

- `account_balance`：现金、净资产、购买力、融资额度、风险水平。
- `stock_positions`：数量、可用数量、成本。
- `PortfolioContext`：账户级总盈亏摘要。当前官方摘要没有可靠拆分已实现/未实现，因此 PA 不伪造拆分值。
- PA 管理的单次交易盈亏以实际成交记录计算，账户接口作为交叉核对。

## OKX

### 规格和账户预检

- 私有接口鉴权必须有 API Key、Secret、Passphrase。
- 先校准服务器时间，再签名；请求设置短有效期。
- 通过 `/api/v5/account/instruments` 读取当前账户可交易品种。
- 只接受 `state=live`，按 `tickSz`、`lotSz`、`minSz` 校验，不自动四舍五入扩大风险。
- 现货使用 `tdMode=cash`、数量统一为基础币数量；现货不允许新开空仓。
- 永续使用用户配置的 `cross` 或 `isolated`，读取并适配当前 `net`/双向持仓模式，不擅自修改账户模式或杠杆。
- 通过 `/api/v5/account/max-size` 校验可交易数量。
- 永续额外通过只读杠杆接口记录当前杠杆，但不自动修改。

### 入场、保护和退出

- 普通入场使用 `/api/v5/trade/order`，携带唯一 `clOrdId`。
- 突破入场使用触发策略单；触发后先持久化交易所生成的普通子订单 ID，部分成交撤余单只撤该子订单，不能把父策略单当作剩余挂单重复处理。
- 部分成交时撤销剩余数量，仅管理实际成交量。
- 现货成交后先读取成交明细：基础币扣费会从成交总量中扣除，再按数量步长向下取整，余量记为不可管理 dust；报价币手续费不减少基础币持仓。按最终可管理净数量建立最多两笔 OCO，每笔对应一档止盈并共享同一止损；无法分成两份时只使用第一档止盈并记录原因。
- 券商只返回“已成交”但缺少成交数量时，必须由成交明细确认数量与加权均价；无法确认时停止写操作，禁止使用计划数量建立保护。
- 永续成交后建立两档分批止盈和一笔止损，退出单使用正确的 `posSide` 与 `reduceOnly`/平仓语义。
- 主动离场先取消未触发保护单，再按实际剩余仓位市价退出。
- 所有提交结果同时检查顶层 `code` 和逐项 `sCode`。

### 资金与盈亏

- `/api/v5/account/balance`：按所选计价币映射权益、现金、可用余额、未实现盈亏，并把非零现货余额映射为持仓。
- `/api/v5/account/positions`：永续持仓、均价、标记价、未实现/已实现盈亏、杠杆。
- `/api/v5/trade/fills`：永续关闭成交使用交易所 `fillPnl`，避免把合约张数误当基础资产数量。
- 现货单次交易盈亏当前按实际买卖均价与数量计算毛盈亏；券商费用仍以 OKX 账户/成交记录为准。交易所没有可靠提供的账户总盈亏或已实现盈亏不做跨币种拼接，字段保持未知。

## 轮询与恢复

- 默认每 2 秒轮询活动执行；同一券商请求串行化并遵守官方限流。
- 每个外部动作前先写入意图，成功后再写券商 ID 和结果。
- READY 计划的路由指纹包含券商、环境、账户、产品、品种、数量、OKX API 地址/保证金模式、Longbridge 盘外交易开关和入场超时；配置变化会让未提交计划失效。
- 执行一旦开始，适配器只使用计划中已持久化的不可变路由快照，不允许当前设置把旧活动订单改指向另一个账户、环境或 API 地址。
- PA 启动时只恢复监控，不恢复会话实盘开关，也不自动创建新交易。
- 对账优先使用券商订单 ID，其次使用客户订单 ID/Longbridge 备注。
- 即使会话未启用写操作，结果未知的入场、保护或撤单也继续只读查询；只有确认不存在且重新完成启用后才允许新写入，不能靠重启盲目重发。
- 每轮订单对账后按该执行记录的持久化账户/路由刷新资金和持仓；刚进入终态的执行也会补写最后一次账户快照。界面展示的持仓来自该快照，而不是当前配置猜测。
- 活动执行未对账完成时，禁止同一券商、账户、品种创建第二笔执行。

## 硬验收

自动化测试不得访问真实交易接口，必须证明：

- AI 扩展字段无法改变账户、品种、数量或杠杆。
- 演示/历史/异常/不下单/低置信度/品种不匹配均被阻断。
- 相同分析记录重复到达不会重复下单。
- Longbridge 安全回退矩阵正确，提交后绝不回退。
- OKX 现货做空、停牌品种、数量/价格不合规格、账户模式不匹配被阻断。
- 两券商均覆盖接受、拒绝、部分成交、成交、撤单、保护、主动退出、关闭和 UNKNOWN 对账。
- 重启后能恢复活动执行且不会自动重新启用实盘。
- 账户资金、持仓、已实现/未实现盈亏能映射到 PA 状态。
