# PA_Agent — Codex 项目规则

本文件是 PA_Agent 的项目级执行规则摘要，用于本地 Codex、代码审查者和外部规划模型理解真实约束。它不包含全局机器配置、凭据或其他项目内容。

## 1. 项目边界

- PA_Agent 是独立量化分析与交易系统；上下文、代码、Git、验证、文件包和模型任务均独立处理。
- 当前主线是 PA_Agent 自身的行情、AI 分析和未来实盘执行层，不设计跨项目共享执行层或信号接入。
- 前端改版必须先以当前功能和后端真值编写 PRD，再由 Stitch → Pencil → Figma 形成设计稿；设计未验收前不得直接改生产 PyQt 视觉，也不得把尚未实现的后端能力画成可用。

## 2. 设计与开发

- 先读 `CONTEXT.md`、`lessons.md`、README、配置说明和本文件，再设计、后编码。
- 从原始交易目标出发；真正改变账户、产品、数量、杠杆、风险或自动化方式的分叉必须停下来，一次只问用户一个问题。
- 只实现当前目标所需的最小完整方案，不顺手重构、换框架或修改无关代码。
- 工具和框架按“成熟开源社区方案 > 小范围高质量开源方案 > 自行实现”比较；复用前核对许可证、维护状态、真实接口、现有架构接缝和失败回退，不能仅凭产品介绍引入。
- 问题尽早暴露：不静默降级、不猜字段、不用启发式补丁掩盖账户/API/状态错误。
- 外部 API、产品规格、SDK 方法和字段必须先查官方资料或实际只读接口；不凭记忆生成。

## 3. 实盘安全

- 开发、测试、审查、打包和外部模型规划阶段不得发送真实订单。
- 实盘默认关闭、失败关闭；武装状态不跨重启持久化。
- AI 只能生成 `TradeIntent` 候选。账户、产品、方向、数量、杠杆、保证金模式、TIF、风险限额和客户订单号必须由确定性规则补全并验证。
- 超时、网络错误或状态未知时先按客户订单号对账，禁止盲目重发或跨账户重发。
- “订单已受理”不等于“已成交”；部分成交、保护单缺失、只减仓和平仓方向必须显式建模。
- demo/replay、模拟环境和真实环境必须在生命周期、凭据、账本与界面状态上隔离。

## 4. 凭据与数据

- 凭据只从仓库外环境文件或进程环境读取，不写入代码、Git、日志、分析记录、异常栈、测试夹具或移交包。
- `.env`、真实 `config/settings.json`、日志、分析记录、订单/持仓状态、行情/训练数据、数据库和模型文件不得提交。
- 配置示例只能使用空值或明显占位符；提交前必须对 staged snapshot 运行密钥扫描。

## 5. Git 与协作

- 不擅自创建分支、worktree、tag，不改写历史，不强推。
- 混合工作区只暂存用户确认的明确文件，禁止 `git add .` 和 `git add -A`。
- 提交前检查文件清单、完整 staged diff、密钥、大小/类型、私有远程权限和实时 SHA；提交后验证本地、跟踪分支与 GitHub SHA 一致。
- 不覆盖用户、旧任务或其他 Agent 的改动。

## 6. 验证与审查

- 验收覆盖空输入、格式错、超时、权限不足、并发、部分成交、重启、缓存/历史状态和误用路径。
- 测试报告只陈述实际通过/失败数量；超时或没有最终汇总时不得推断结果。
- 量化策略上线、实盘执行和关键提交必须由独立审查者从需求完整性、逻辑正确性、边界情况、代码质量、测试覆盖和实际运行结果六方面复验。
- 审查问题分“阻塞落地”和“可选优化”；只强制修复有明确依据的阻塞项。

## 7. 文档纪律

- 阶段完成更新 `CONTEXT.md`；用户纠正后更新 `lessons.md`。
- 已完成、候选、未实现和待验证事实必须分开，不能把架构建议写成现成功能。
- 外部大模型的计划不是执行授权，也不是本机可执行方案；必须先按 `LOCAL_EXECUTION_CONTEXT.md` 由本地 Codex 校正。
