# PA_Agent 前端重构 PRD

状态：设计输入稿，不是生产界面实现
范围：AI 大模型设置、交易执行中心
原则：先把后端真实状态定义清楚，再由 Stitch → Pencil → Figma 形成设计稿；设计工具不得虚构后端能力。

## 1. 用户目标

用户打开 PA 后，应在很短时间内看懂两件事：

1. 当前 AI 通过哪种方式接入，能选哪些模型，是否真的测试通过。
2. 当前交易接入的是哪个券商、哪个环境、哪个账户，PA 正处于入场、保护、监控还是离场阶段。

界面不能把“已保存”“已登录”“已测试”“已激活”“允许下单”混成同一个状态。

## 2. 不允许出现的假功能

- 不允许把模型上下文上限做成可编辑数字。上限由模型和接入方式决定。
- 不允许把 Compact 做成用户可随意打开的假开关。只有官方 Codex 持久线程实际启用时才显示“原生自动压缩可用”。
- 不允许用“测试通过”代替“档案已激活”。
- 不允许把模拟账户、实盘账户或不同券商的资金混在同一张卡里。
- 不允许在后台执行进程、启动对账、减险权限尚未落地时，把它们画成已经可用。
- 不允许为了排版把撤单、补保护、主动离场等减险按钮藏起来。

## 3. AI 大模型设置

### 3.1 第一层：明确区分接入方式

使用两个清楚的入口：

- **订阅登录**
  - 当前范围：Codex（ChatGPT 订阅）。
  - 显示官方 CLI 是否安装、是否已用 ChatGPT 登录。
  - 操作：网页登录、设备码登录、重新检测。
  - 不显示 Base URL 和 API Key。
- **API 接入**
  - 当前范围：DeepSeek、Kimi。
  - 显示 Base URL、API Key、密钥来源和连接测试。
  - API Key 默认遮挡；“显示/隐藏”必须真的改变可见状态。

### 3.2 模型目录

- 主控件是不可随意输入的下拉选择器。
- 每一项同时显示友好名称和精确模型 ID。
- 内部保存精确模型 ID，不能保存界面展示文字。
- “同步并展开”完成后直接展开列表，让用户立即看到可选项。
- Codex 从当前官方 CLI 的账号模型目录读取。
- DeepSeek、Kimi 从当前账号的 `/models` 接口读取。
- 在线同步失败时保留原列表，并清楚显示失败原因；不能把列表清空。
- 只有官方目录暂未收录但用户确认存在的模型，才允许开启“高级手动填写”。

### 3.3 模型能力按目录变化

界面根据当前模型元数据决定是否显示：

- Thinking 开关；
- 推理强度；
- 分析速度或服务线路。

某模型不支持的字段必须隐藏，而不是保留一个无效输入框。

模型上下文上限只读显示：

- 已知：`272,000 tokens（模型固定）`（示例值；实际以当前账号或本机官方目录返回值为准）
- 未知：`尚未确认（模型固定）`

账号实时目录是上下文上限的最高优先级真值，内置目录只能在离线时兜底。保存和重启不能把实时值改回旧的内置值。上下文元数据变化不属于认证变化，不能让已测试档案无故变成“需要重新验证”。

### 3.4 Compact 状态

Codex 订阅档案显示：

- 正式两阶段分析：一次性线程，不复用历史。
- 自由追问：复用官方 Codex 线程。
- 自动 Compact：由 Codex 在达到模型阈值时执行。
- 当前线程可恢复：是/否。

DeepSeek、Kimi 显示：

- 不具备 Codex 原生 Compact。
- PA 只显示最近一轮上下文和累计 Token。

### 3.5 档案状态

每个档案分开显示：

1. 已保存；
2. 登录/密钥是否存在；
3. 真实连接测试是否通过；
4. 是否为当前激活档案。

按钮顺序：

`测试并保存` → 测试通过后 `激活此档案`

测试失败不能覆盖当前正在运行的有效档案。激活失败必须保留旧客户端和旧配置。

## 4. 交易执行中心

窗口名称从“实盘交易”改为“交易执行”，因为同一窗口也管理模拟账户。

### 4.1 顶部安全状态条

始终显示：

- 券商与环境：例如 `OKX · Demo`；
- 账户：例如 `Longbridge · 日内融资子账户`；
- 执行后台：运行 / 停止 / 需要关注；
- 新入场权限：允许 / 禁止；
- 减险权限：可用 / 阻断；
- 最近一次券商对账时间。

任何字段未知时直接显示“未知”，不能用绿色或默认值掩盖。

### 4.2 页面信息架构

使用六个稳定分区：

1. **连接与账户**
   - 券商、模拟/实盘、账户档案；
   - 只读连接测试；
   - 账户指纹核对结果；
   - 可用资金、净资产、购买力、当前持仓与盈亏。
2. **执行配置**
   - 产品、品种、数量、保证金模式；
   - Longbridge 日内账户回退开关；
   - 当前路由不可变摘要。
3. **权限与自动化**
   - 是否允许生成执行计划；
   - 是否允许新入场；
   - 已有 PA 持仓的补保护、撤单和减仓权限；
   - 自动化授权的有效期和撤销入口。
4. **交易生命周期**
   - 入场 → 成交 → 保护 → 监控 → 离场 → 完成；
   - 当前步骤、券商订单号的安全摘要、数量和价格；
   - 部分成交、请求结果未知、人工关注必须是独立状态。
5. **操作区**
   - 提交入场；
   - 撤销未成交入场；
   - 补保护；
   - 主动离场；
   - 停止新增风险。
6. **异常与审计**
   - 最近错误；
   - 本地账本与券商真值差异；
   - 需要人工确认的孤儿订单或非 PA 持仓；
   - 可复制的脱敏诊断摘要。

### 4.3 权限必须分成两类

**新增风险权限**控制新入场。它需要用户明确授权，并在路由、账户、产品或数量改变后自动失效。

**减险权限**只允许：

- 撤销 PA 自己创建的未成交订单；
- 给 PA 已确认持有的仓位补保护；
- 减少或关闭 PA 已确认持有的仓位。

减险动作不能增加仓位，数量不能超过券商真实持仓。即使新增风险权限已关闭，减险动作仍应可用；账户身份不一致时两类写操作都必须停止。

### 4.4 Longbridge 回退必须可解释

界面显示：

- 首选账户；
- 是否允许从日内融资子账户回退到综合账户；
- 回退前的两个账户预检结果；
- 最终实际选择账户；
- 回退原因。

只允许在提交前、且日内账户明确为购买力或交易资格不足时回退。网络、认证、超时、限流、未知结果或已经提交后绝不回退。模拟账户绝不回退到实盘账户。

### 4.5 交易状态表

| 状态 | 用户看到的文字 | 允许新增风险 | 允许减险 |
|---|---|---:|---:|
| READY | 等待提交 | 按授权 | 不适用 |
| SUBMITTING | 正在提交，禁止重复操作 | 否 | 只读 |
| ENTRY_PENDING | 入场单等待成交 | 否 | 可撤入场 |
| PARTIALLY_FILLED | 已部分成交，正在撤余单并补保护 | 否 | 是 |
| OPEN | 已持仓且保护已核对 | 否 | 是 |
| EXIT_PENDING | 正在离场 | 否 | 只允许继续对账 |
| CLOSED | 已完成 | 否 | 不适用 |
| UNKNOWN | 券商是否收到请求尚未确认 | 否 | 只读对账 |
| NEEDS_ATTENTION | 需要人工处理 | 否 | 仅显示明确安全的操作 |

## 5. 后端契约：设计稿必须以此为边界

### 5.1 独立执行后台

交易监控不能依赖 GUI。应拆出独立的 `ExecutionWorker`：

- Windows 登录后由 WinSW 监管启动；
- GUI 只负责配置、授权、查看状态和发出命令；
- GUI 关闭后，已入场订单的对账、保护和离场仍继续；
- Worker 崩溃后自动重启，但不得自动重复下单。

### 5.2 启动对账

Worker 启动时必须同时读取：

- SQLite 中的活动执行；
- 券商侧带 PA 确定性标记的订单和成交；
- 券商真实持仓。

能够按客户订单号或备注确认归属的记录才接管。仅发现一笔无法证明属于 PA 的持仓时，只标记为“非 PA/归属未知”，不得擅自平仓。

### 5.3 持续对账

每轮对账比较：

- 本地剩余数量；
- 券商订单状态；
- 券商成交数量；
- 券商真实持仓；
- 保护单覆盖数量。

任何不一致先停止新增风险，再决定补保护、减仓或人工关注。不能用计划数量覆盖券商真实数量。

### 5.4 Longbridge

- 继续使用官方 SDK。
- 私有订单推送为主，REST 查询为补充。
- 全账户共享交易限速器：不超过官方 30 次/30 秒，并保证相邻请求至少 0.02 秒。
- 活跃订单快速对账；稳定持仓和账户资金降低刷新频率。

### 5.5 OKX

- 当前自研适配器在切换前继续作为唯一写入者。
- 对 NautilusTrader 的 OKX Demo 适配做独立兼容实验，验收现货、永续、私有推送、保护单、部分成交、断线恢复和启动对账。
- 实验阶段不允许 Nautilus 与旧适配器同时写同一账户。
- 只有全部契约通过后，才把写入权一次性切换给 Nautilus；旧适配器只读影子核对。

## 6. 设计工具输入

### Stitch

先生成以下两个桌面端页面的视觉方向：

1. AI 模型设置；
2. 交易执行中心。

要求专业金融终端风格，信息密度适中，重点状态一眼可见；不照搬某个产品品牌，也不改变本 PRD 的状态和权限语义。

### Pencil

用状态流方式画出：

- 正常入场到离场；
- 部分成交；
- 请求结果未知；
- GUI 关闭但 Worker 继续；
- 启动发现孤儿订单；
- Longbridge 日内账户安全回退。

### Figma

在 Stitch 视觉方向和 Pencil 状态流通过后，建立可复用组件：

- 状态徽标；
- 账户卡；
- 生命周期步骤条；
- 风险/减险按钮；
- 脱敏诊断抽屉；
- 模型档案卡和模型目录选择器。

## 7. 设计验收

- 用户无需阅读文档，就能区分订阅登录和 API 接入。
- 用户能直接看到当前账号可选模型，不需要猜模型 ID。
- 上下文上限不可编辑，Compact 不被伪装成开关。
- 用户能在一个屏幕内确认券商、环境、账户、新增风险权限和减险权限。
- GUI 关闭后已有执行仍由后台监控。
- 任何未知状态不会显示成成功。
- 配置有未保存变化时，只禁止新增风险；对已有 PA 订单的安全撤单、补保护和离场不能被一并禁用。
- 设计稿中的每个状态和按钮都能映射到明确的后端接口；不能映射的内容必须删除。
