# GPT-5.6-sol 移交说明

## 1. 项目真实状态

PA_Agent 是本轮实盘扩展的主项目。当前能从 MT5、TradingView、Longbridge、yfinance 和 AkShare 获取行情，并完成两阶段 AI 分析；当前代码不具备真实下单能力。

以下主要改动已随功能提交 `3d9353f8579e6d661fd314ab6b9e91016d9fdd96` 发布到私有仓库 `Jinqingchang/PA_Agent` 的 `main`：

- Longbridge 只读行情源，仅创建 `QuoteContext`，不创建 `TradeContext`。
- 数据源事务式切换、每数据源独立品种与连接状态。
- 多套 AI 模型档案保存、真实连接测试、原子切换、Thinking/effort 能力适配。
- 自由追问会话生命周期修复。
- PA_Agent 的全部前端重设计已按用户要求废弃；后续不得把视觉改版扩大为主任务。

## 2. 当前主目标

在不让 AI 分析结果直接变成不可控订单的前提下，为 PA_Agent 增加可审计、默认关闭、失败关闭的实盘执行层：

1. Longbridge 综合账户与日内融资子账户。
2. OKX 第一阶段优先黄金现货类产品和黄金永续合约，架构保留后续增加其他品种的能力，不做永久单品种硬编码。
3. AI 只生成交易意图；账户路由、数量、产品代码、保证金模式、杠杆、有效期和风险限额必须由确定性规则补全并验证。

## 3. Longbridge 业务需求

以下是用户提供的业务背景，模型必须用 Longbridge 官方文档和实际账户只读接口再验证，不能当成无条件平台保证：

- 综合账户支持的产品范围更完整，包括期权，但融资效率可能低于日内子账户。
- 日内融资子账户不做期权，日内融资不收利息，杠杆上限与标的可用性会动态变化。
- 某些多倍杠杆 ETF 可能有时可在日内子账户交易、有时不可交易，不能通过名称或静态表推断。
- 安全回退必须先在日内账户做可购数量/保证金预检；仅在明确不支持或可购数量为零，且已确认没有订单被受理时，才能重算后转综合账户。
- 超时、网络未知、已受理、部分成交或状态不明时禁止跨账户重发。
- 两套实际凭据仅存在于仓库外的本机环境文件，不在本移交包中。

## 4. OKX 黄金产品事实与未决分叉

截至 2026-07-16，官方公开产品接口显示：

- `XAUT-USDT` 是代币化黄金现货，不是传统券商/MT5 意义的 XAUUSD 现货。
- `XAU-USDT-SWAP` 是以 USDT 作为保证金与结算币、跟踪现货黄金的线性永续合约，无到期日；当前 1 张代表 `0.001 XAU`，最小 1 张，价格步长 `0.1`。
- OKX 还有 USD 到期合约与 X-Perp，它们不应被静默映射为上述普通永续。

用户已明确的是“优先完成 XAUUSD/黄金的现货类产品和永续合约，之后可扩展其他品种”；尚未正式确认首期现货是否接受 `XAUT-USDT`。

OKX Key/Secret 已在仓库外的本机 `env` 中，Passphrase 尚缺，实盘开关为关闭。用户提供的 Key 当前具有提币权限且未绑定 IP；即使是专用 Key，启用实盘前也必须收紧为只读+交易、无提币权限，并完成 IP 白名单与账户级只读预检。

## 5. 现有代码的关键边界

- `AnalysisRecord` 是完整分析记录，但不包含券商、账户、产品类型、下单数量、杠杆、TIF 和客户订单号。
- `trade_logger.py` 是交易机会记录，不是强一致订单账本。
- 建议的生命周期接入点是完整记录已持久化后的 `MainWindow._on_record_ready_impl(record)`，不是仅携带决策字典的 `_on_analysis_finished(decision)`。
- 演示回放会经过与真实分析相同的信号路径，执行层必须在生命周期和适配器两处硬阻断 demo/replay。

## 6. 候选最小架构（待论证，不是已批准实现）

```text
AnalysisRecord
  -> TradeIntent 规范化
  -> 确定性风险闸门
  -> 人工确认 / 临时武装
  -> Broker Router
       -> Longbridge 双账户预检与安全回退
       -> OKX 产品注册表与动态规格校验
  -> SQLite 强订单账本
  -> 提交 / 查询 / 撤单 / 成交 / 保护单对账
```

最小状态机需覆盖：`CREATED -> RISK_APPROVED -> AWAITING_CONFIRMATION/ARMED -> SUBMITTING -> ACCEPTED -> PARTIALLY_FILLED -> FILLED`，并显式存在 `BLOCKED/REJECTED/EXPIRED/UNKNOWN/RECONCILING`。超时后必须按客户订单号查询，禁止盲目重发。

## 7. 不可突破的安全不变式

- 开发、测试、审查和移交阶段不得发送真实订单。
- 实盘默认关闭，武装状态不跨重启持久化，demo 与 live 凭据、账本和界面状态分离。
- 不自动切换 OKX 账户模式或持仓模式，不猜测数量单位、产品代码或杠杆。
- 订单 API 返回“已受理”不等于“已成交”。
- 平仓使用只减仓语义；保护单缺失时立即禁止新开仓，不得把主单受理当成仓位已受保护。
- 凭据只从本机环境变量/忽略文件读取，不写入 Git、分析记录或异常栈。
