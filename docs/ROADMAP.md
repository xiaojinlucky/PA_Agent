# PA_Agent 统一路线图

## 终态

PA_Agent 的终态是 Windows PyQt6 桌面上的 OKX 永续全自动交易控制台：首发单品种 `XAU-USDT-SWAP`、15 分钟、单策略、单 PA 专用账户、USDT 本位、全仓、净持仓、可多可空。AI 只产生结构化交易意图；确定性规则负责账户、品种、数量、杠杆、保证金、客户订单号、幂等、对账和恢复；`ExecutionWorker` 是唯一券商写入者。

“全自动”指日常运行不逐笔等待人工确认；不代表绕过三道刹车：第一次打开真实交易必须人工启用，断网或账户身份不匹配时停止新增风险，订单结果未知时先按客户订单号对账且绝不盲目重发。

## 当前基线

- 当前 main：`1a04c144f810ffb486280ed8a1875ff0130bb070`。
- OKX 公共行情源已存在并已注册到数据源工厂、接入主界面；阶段 0 只做审核、验收和能力边界记录，不从零重写。
- 当前单笔执行状态真值为 `ExecutionState` 的 13 个枚举值，`PROTECTING` 属于活动状态。产品目标中的自动循环状态和持仓生命周期状态不是现有枚举，后续必须显式映射。
- `records/execution.sqlite3` 继续是唯一逐笔交易事实账本；生命周期表只能引用和汇总它。

## 阶段路线

### 阶段 0：基线对齐与 PRD 落库

- 目标：让文档事实与当前代码基线一致，并把产品 PRD、工程移交硬验收和 Stitch 设计提示词正式归档。
- 主要改动：修正活动文档的旧 SHA；记录 OKX 行情源能力边界；记录 13 状态执行真值和目标态映射；落库三份 PRD；写入安全不变量和本路线图。
- 进入条件：无。
- 硬边界：只改文档，不改交易执行逻辑，不改状态枚举，不发订单。
- 产出：`docs/prd/`、`docs/ROADMAP.md`、`docs/SAFETY_INVARIANTS.md`、基线核验记录。

### 阶段 1：只读工作台与 OKX 行情链验收

- 目标：把真实行情、PA 分析、账户、Worker、执行、订单、保护和对账状态组成只读 Read Model，建立左侧导航和交易工作台。
- 主要改动：审核现有 `OkxSource`；建立带来源、时间和“计划/已确认”语义的读取层；保留现有写入链路，不加入人工下单面板。
- 进入条件：阶段 0 文档基线通过。
- 产出：只读工作台、页面—字段—状态—交互映射、真实截图和定向验收。
- 当前进度（2026-07-23）：读取层基础和主窗口只读状态条已完成并通过定向回归；左侧导航、完整页面、截图和 OKX 端到端验收仍未完成。

### 阶段 2：监督智能体与自动分析循环

- 目标：新增独立监督角色、主模型/备用模型/确定性兜底，并把分析调度从 GUI 生命周期移出。
- 主要改动：监督输入输出契约、角色档案、K 线唯一处理键、持久自动策略状态、启动/持续对账；所有动作仍只生成持久命令。
- 进入条件：阶段 1 只读工作台验收通过。
- 旧工单归位：`WO-002` 启动对账、`WO-003` 持续对账。

### 阶段 3：动态仓位、杠杆与持仓协调

- 目标：按 10% 生命周期风险预算计算数量，接入动态杠杆、同向加仓、统一保护、减仓和反手。
- 主要改动：风险引擎、父级生命周期、逐笔执行腿、保护版本和生命周期锁；反手必须先确认旧仓归零。
- 进入条件：阶段 2 自动分析循环和监督契约验收通过。
- 产出：加仓/保护/反手完整失败路径和 Demo 验收。

### 阶段 4：持久恢复与停止机制

- 目标：实现持久运行目标状态、暂停新开仓、紧急清仓、连续完整止损暂停、回撤停止和资金流水校正。
- 主要改动：把日常自动运行状态与环境硬门分开；重启只在恢复门禁通过时恢复新增风险，未知写操作只对账。
- 进入条件：阶段 3 持仓协调验收通过。
- 旧工单归位：`WO-004` Longbridge 共享限速、`WO-005` Longbridge 私有推送作为多券商扩展；`WO-006` OKX Live 权限整改作为真实交易启用前置。

### 阶段 5：完整复盘与扩展准备

- 目标：生命周期复盘、模型/提示词版本追踪，以及多品种、多策略、多账户扩展接口。
- 主要改动：生命周期聚合只引用逐笔账本；增加复盘、资金流水和配置快照视图；不提前扩张首发产品范围。
- 进入条件：阶段 4 停止与恢复机制验收通过。

## 每阶段共同验收

不得把设计稿、模型建议、持久计划或 Demo canary 说成券商已确认事实。测试必须覆盖重复 K 线、错误输入、超时、未知订单、部分成交、重启、并发、外部仓位和保护缺失；任何阶段都不得新增第二条券商写入链。
