# PA_Agent 安全不变量

这些规则贯穿阶段 0–5。任何后续功能若不能保持它们，功能不进入下一阶段。

## 三道自动运行刹车

1. 第一次打开真实交易必须由用户人工启用一次；日常运行不逐笔要求确认。
2. 断网、账户身份不匹配、最近成功对账过期、外部同品种仓位或其他环境硬门不满足时，停止新增风险，但继续允许只读监控、已有保护和减险对账。
3. 订单、保护、撤单或离场结果未知时，先按持久客户订单号/券商订单号对账，禁止盲目重发、跨账户重发或用新订单覆盖未知事实。

## 写权限与账本

- AI、自动分析协调器、监督智能体、风险模块、GUI 和 `ExecutionController` 不持有券商写权限；它们只能生成经过校验的持久意图或命令。
- `ExecutionWorker` 是唯一可以创建私有执行服务/执行适配器并执行券商写操作（提交/撤销订单、建立/更新保护和离场）的进程；公共行情模块可以建立只读客户端，但不得获得交易写权限。
- `records/execution.sqlite3` 是唯一逐笔交易事实账本；新增生命周期、风险和复盘数据只能引用或汇总逐笔事实，不能覆盖或竞争事实归属。
- 任何券商写调用都必须先持久化意图，再在 Worker 中原子认领并使用同一账户、品种、策略版本、快照摘要和生命周期锁复核。

当前代码仍使用短期 `NEW_RISK` 租约；持久自动策略、策略版本/快照锁和生命周期锁的完整组合属于后续阶段目标。这里写的是不可破坏的设计边界，不把目标能力冒充为当前已经完成。

## 数据与展示

- AI 只能产生交易意图；账户、品种、数量、杠杆、保证金、客户订单号和风险上限由确定性规则补全并校验。
- `计划/建议/命令已入队/已提交/部分成交/已确认` 必须分开。只有 Worker 对账确认的订单、成交、仓位和保护才能使用事实性成功文案。
- 凭据只来自仓库外环境或系统安全存储，不进入代码、Git、日志、分析记录、异常栈、测试夹具或交付包。
- 开发、测试、审查和规划阶段不发送真实订单；Demo canary 只证明技术链路，不证明策略绩效或 Live readiness。
